
# zic Product and Engineering Specification

本文件是规范，不是实施报告。`MUST` 表示发布合同，`SHOULD` 表示默认要求，`MAY` 表示可选行为。实现和验证状态见 `IMPLEMENTATION_STATUS.md`。

## 1. 产品范围

zic MUST 支持 Android 上的本地/远程漫画、LTR/RTL/纵向阅读、静态图片、Animated WebP、partial/resume/offline artifact、漫画源浏览与受控插件扩展，以及本地 Debug Trace 导出。 纵向Reader的异步尺寸更新 MUST 在active scroll期间冻结所有会改变当前viewport前缀的sliver geometry；idle采用这类新geometry时 MUST 以layout-time correction原子维持top-pixel连续。DecodeSession首个成功frame MAY触发尺寸事实提前解析，但Reader页面几何的最终authority MUST是source canvas而非decoded raster；Pipeline只读`PipelinePageDimensionsFeed` MUST携带dimension basis并优先`PageAsset`/WebP source canvas，decoded raster仅可作为provisional fallback且 MUST NOT覆盖已知source canvas。VP8X/VP8/VP8L source canvas解析 MUST只依赖其固定header，不得等待整个compressed image chunk；presentation output/surface raster MUST NOT经UI尺寸回调成为Reader source geometry。`DownloadSession` MUST持有generation-local source-metadata prefix并可投影`sourceCanvasWidth/sourceCanvasHeight`；该prefix不得复制正文，且Pipeline/PageStream MUST从physical ingress读取source metadata，MUST NOT直接从可能为空的session `Artifact`猜测resident body。设备诊断命中该路径时source MUST记录为`physical-ingress-source-canvas`。 Resident replay MUST区分未绑定`DownloadResidentReplaySource(session,endExclusive)`与physical-generation bound `DownloadResidentReplayChunks(endExclusive)`；`DownloadSession`只能消费bound capability，Pipeline/registry只能在当前physical session解析后绑定一次。cache/local-source backend选择 MUST由`CompositionDownloadTransferRuntime`拥有，Pipeline MUST NOT自行实现resident replay backend routing。该feed MUST NOT暴露Flutter `ValueNotifier`/`ValueListenable`，consumer attach MUST可重放retained dimension facts，publish/clear MUST保持Pipeline-private；Pipeline output/progress core同样 MUST NOT直接依赖`WidgetsBinding`/`SchedulerBinding`或Flutter notifier；visual frame boundary MUST通过`PipelineFrameScheduler`由presentation adapter注入，transfer progress MUST通过只读`PipelineTransferProgressFeed`投影。严格位于真实visible tail之后的future page source ratio MAY在active scroll中提前采用，因为它不得改变当前viewport prefix；visible tail及之前的新ratio MUST继续等待idle。不得恢复dev.286 visual extent/OverflowBox workaround，也不得以扩大decode previous1/next2掩盖source geometry authority错误。vertical drag/ballistic期间 MAY 暂缓非可见next2 texture upload，但 MUST 保留next2 decode与current/transition/visible/immediate-next需求。 Android texture的UploadDemand只准备/持有output，真正RGBA Surface copy发生在presentation；同一lease已resident的具体OutputFrame再次present必须零copy复用并记录`platformResident`，不得重复platform blit/schedule。frame identity变化、resize/release使该复用失效；SurfaceProducer重建仍由platform redraw负责。

项目不承诺 DRM 绕过、通用视频播放、社交功能或模型直接操作底层资源生命周期。

### 1.1 首页冷启动

- Home MUST 在本地库的 cover-bearing primary 数据可用后先呈现首页；native media
  prewarm、持久整本队列 restore、外部插件 activation 和 enrichment 不得成为首封面
  请求的硬门槛。
- 外部来源可以在首帧之后 ready；封面 presentation MUST 使用稳定 canonical artwork identity。因来源暂不可用、transport 或 decode 失败后 MUST 保持稳定占位，不得由定时器、App resume、first-frame watchdog、provider eviction 或 loader closure 变化自动重启请求；只有显式来源刷新、资源 revision 或稳定 identity变化才能重新加载。
- 首页每张封面 MUST 独立完成请求和显示；一张封面变慢或 durable response 写入变慢，
  不得阻塞其它已经取得 encoded bytes 的封面。冷 miss MAY 先使用 memory source，持久化
  写入由统一 response cache 后台完成；durable hit MUST 先物化为调用方自持有的 encoded bytes。response cache 的文件路径 MUST NOT 暴露给 `FileImage` 或其它长生命周期 presentation 对象；`FileEncodedResourceSource` 只允许外部稳定本地文件。durable image persistence MUST 区分 `transient` 与 `retained` 生命周期：browse/preview响应 MAY 受 TTL/LRU/maintenance 回收；library/history/details cover MUST 在同一 canonical cache key上晋升为 retained，并且 MUST NOT 被运行期容量/TTL整理删除。metadata refresh MUST NOT 以 comic namespace 粗粒度失效 artwork；retained cover仅由精确 artwork revision/显式整漫画资源删除/用户清缓存移除。
- 首页、书架和详情封面 Presentation State MUST 使用 canonical comic identity，不得因 raw Mihon alias、resume chapter、封面 URL 或 loader closure变化被销毁。Presentation MUST NOT 自己做定时 retry、first-frame watchdog、ImageCache eviction 或短时 Future join；资源重试/缓存所有权唯一属于 `ComicSourceResourceGateway/ResourceCacheManager`。
- 全局网络 User-Agent MUST 是 composition-owned fallback设置，默认采用稳定 Android Chrome UA并可由用户修改。来源 request plan显式 UA、browser-session UA或 source-owned client策略 MUST 优先；全局 fallback不得覆盖来源权威。
- Android Mihon宿主 MUST 能执行 extension/source实际返回的 HTTP(S)媒体 URL；cleartext兼容能力 MUST 在统一宿主网络策略提供，MUST NOT按 WNACG等具体域名/插件维护静态白名单，也不得把 source返回的 HTTP URL擅自改写为 HTTPS。
- Reader页面物理下载 MUST 只有composition `DownloadTransferOwner`一个retry/terminal owner；`LiveCoordinator`只协调本Reader demand与decode/upload。runtime标记transient/retryable的失败 MUST投影为`ErrorCode.network`并受provider的有界RetryPolicy控制；非retryable/source失败与网络重试耗尽 MUST在当前physical transfer demand内终止，source snapshot listener、Reader finally或Presentation MUST NOT另行无界重提。
- 新Reader消费已有committed/promoted physical `DownloadSession`时，Reader-local native ingress MUST 以异步 synchronized projection join恢复；projection创建/重放 MUST NOT同步阻断 DemandPlan reconcile，失败 MUST 只终止该consumer projection而不得降低physical artifact/partial authority。 Reader source listener MUST保存logical DownloadId当前实际绑定的physical session/projection generation；同logical id重新解析到不同physical session，或same DownloadId对应新的DownloadSession对象时，旧listener/Reader-local ingress/decode source binding MUST机械失效并换绑，新physical `sourceReady` MUST可重新唤醒waiting decode，MUST NOT因旧logical listener缓存吞掉wake。
- Reader navigation/current/requested page MUST 独立于 DecodeTarget、download owner与pipeline reconcile生命周期；Reader observation callback MUST enqueue后再reconcile，pipeline错误不得阻止viewport jump/page-request acknowledge。Reader-local viewport/playback projection MUST先于/独立于demand reconcile推进，即使某lane reconcile失败也不得因此丢失viewport事实。DecodeTarget变化 MUST 更新既有PipelineController target并通过后续enqueue observation从当前DemandPlan增量重算，MUST NOT detach binding或把download demand先清空再重建，并 MUST复用同一个ReaderController。
- Download demand MUST按consumer scope独立持有；应用级`PersistentDownloadComposition` MUST持有唯一durable store、`ArtifactCacheManager`与`CompositionDownloadTransferRuntime`，Reader current/prefetch及显式chapter command MUST对exact `DownloadId`共享同一physical `DownloadSession`/writer/network/retry/hot partial，whole-comic MUST只聚合chapter command而不得建立第二physical owner。同一exact id已有queued/active task时，revision变化 MUST只更新该task priority并保持task key稳定。runtime source/media evidence MAY更新事实缓存，但只有当最终DemandPlan的role/resource/priority/reason/watermark/flow/keep等调度语义改变时才 MUST提交新policy revision；纯诊断/evidence计数变化 MUST NOT进入Coordinator。`expirationRevision` MUST只作为surviving demand的liveness metadata原位刷新，MUST NOT参与Download/Decode/Upload的scheduler diff equality，也 MUST NOT单独触发cancel/submit/follow或physical `replaceDemands`。多个claim的有效priority MUST取最大值而不是求和；priority只决定竞争顺序，required completion MUST独立决定低优先级显式下载是否必须最终完成costly full-body catch-up。一个consumer退出/取消 MUST只撤销自身claim；当最后logical claim归零而network MUST只表示正文由外部immutable authority可重放，不得推断durable cache已拥有正文；`ByteResponseDisposition.durableImmutable`与`ByteResponseBodyAuthority` MUST正交，只有artifact-cache authority才可证明durable body ownership。artifact-cache durable body一旦确认authority MUST以`responseRetained=false`同时释放NetLane network body-read permit与transport/source lease并继续本地读取；其body带宽 MUST只由`ArtifactCacheReadScheduler`调度，不得与remote NetLane资源双重计数。source-resident promotion MAY保持session artifact为空且不得因Reader展示自动持久化；显式durable command完成前 MUST通过composition replay authority验证boundary/validators并materialize到唯一ArtifactCacheManager/store且确认durable artifact可读。每个Reader仍 MUST通过自己的`DownloadIngressProjection`消费encoded prefix，decode/upload/presentation保持局部；late projection replay默认 MUST在追平physical committed boundary期间保持source不可见；但已sniff为WebP的nonresident hot partial MAY按decoder-owned playable/required/unresolved prefix contract先发布最小Reader-local可播放prefix，再在同一native source上增量追平artifact suffix并仅在稳定边界后加入live fan-out。early publish后 MUST NOT通过rebuild/reset替换已对decode可见的same-generation source；physical partial availability、network need与Reader-local decode availability MUST保持独立。跨版本hot writer MAY仅通过acquire-time verified physical alias共享：新exact demand尚未创建session，且direct verified equivalence唯一指向已有有authority的physical session时可在acquire前join；两个已经存在的physical session MUST NOT事后merge，source-resident且非artifact-cache authority的body MUST NOT跨版本join。共享后claim MUST保留自己的exact URI/source bucket；committed partial MAY由physical session跨direct verified equivalent request共享，但resume validator MUST绑定到实际产生它的provider exact URI，MUST NOT把physical anchor或其他provider的ETag/Last-Modified用于当前URI的strong Range；scope不匹配时 MUST保留partial并按既有validatorless overlap规则验证continuity。显式durable command完成前仍 MUST materialize自己的exact durable ID。 若required exact ID与physical session anchor不同，durable handoff MUST直接materialize required exact target，MUST NOT为了完成该command先强制持久化physical anchor再复制。 verified relation MUST只在新的physical acquire发生时影响transfer identity；artifact promoted commit MUST NOT通过observer异步取消、重启或改写任何已经存在的independent physical session，Reader/consumer/cache均 MUST NOT持有late takeover委托。 physical async prepare MAY恢复cold/session-local artifact；若prepare后session已promoted或完整partial可在无transport条件下本地seal/promote，TransferOwner MUST在provider transport lookup/lease及`downloadStarted`之前完成短路，MUST NOT把local completion记为network - Reader page 的 scheduler cancellation/priority MUST 跨 `DownloadJob -> cache/read-through transport -> source request-plan -> external runtime` 保持同一 task identity。任何透明wrapper在下层支持`ControlledTransport`时 MUST保持该capability与同一个`TaskControl`，cache miss不得退化为无control的`open()`。Venera MAY 为JavaScript安全保持单 invocation context，但其内部排队 MUST在permit transfer时尊重实时priority并丢弃cancelled waiter；若同一scheduler `TaskControl`在waiter存续期间发生priority变化，gate MUST保留实时priority用于permit排序；只有waiter从低于1000跨入current=1000，或controlled active从current=1000向下跨出且队列中已有新的current=1000 waiter时 MAY动态重新评估preemption；普通780↔900变化与非current active demotion MUST NOT触发不可逆cancel。runtime MUST NOT写回priority或创建独立policy。active controlled invocation取消 MUST下沉到requestId cancellation。Venera controlled request-plan gate SHOULD以previous=780作为pressure floor并继续要求至少40分rank差：780对760不得抢占，780对明显更低rank active work MAY请求取消。`loadEp`的page identity与按需`onImageLoad` request-plan MUST和最终图片body transport区分；最终无状态图片HTTP由`SourceResourceTransport`/host transport执行，`__zicCancel(requestId)`只取消JavaScript plan invocation及其bridge-scoped工作，MUST NOT成为最终图片HTTP的第二cancel owner。Venera native cancellation MUST中止该requestId所属HTTP connection/call以及正在阻塞读取的 response `InputStream`；Venera bridge 的 `delay` MUST为异步、按requestId可取消的 JavaScript timer/Promise，MUST NOT以 native `Thread.sleep` 阻塞 WebView bridge线程。单上下文 invocation permit MUST等JavaScript真正 `finished(requestId)` 后才释放；仅向Dart返回“cancelled”不得提前制造第二个并发JS invocation。不得用独立FIFO覆盖NetLane决定，也不得增加Venera并发来模拟抢占。source response/request MAY携带只读stage diagnostics用于trace，包括gate wait、runtime invocation、JS hook、hook内bridge network与host-open；scheduler/retry/cache MUST NOT依据该观测元数据决策。 通用 external-runtime invoke function type MUST NOT因为该观测需求增加 timing callback；gate/runtime timing MUST限制在 resolve-resource 专用私有 invocation seam，普通 browse/details/account不得依赖该内部诊断。Venera source传给`Network.*`的`cache-time`与`prevent-parallel` MUST作为runtime network控制字段消费并在origin HTTP前移除，MUST NOT直接转发给服务器；Venera source-requested resolver cache MUST由native plugin-driver host/runtime-network owner持有，并以`pluginId/pluginVersion/sourceKey`分区；单个WebView/bridge MUST只消费且不得在自身close时清空，同namespace bridge replacement SHOULD继续复用仍新鲜的resolver entry。该cache MUST有界、保留Cookie/请求header身份差异、不得进入Reader/Pipeline artifact所有权。`cache-time: long` SHOULD对齐Venera约6小时语义；普通短命中 SHOULD约5秒。当前单invocation runtime已提供比same-path prevent-parallel更强的物理串行保证，不得因此新增第二scheduler或JS并发。Venera bridge正常完整消费Network HTTP response后 SHOULD关闭response stream并保留平台持久连接复用机会，MUST NOT无条件disconnect；异常或request-scoped cancel MUST仍物理中止connection/stream。
- Native incremental decoder MUST NOT 在完整 WebP decode、scale、composite或 frame copy期间持有 encoded byte source读锁。source lock临界区 MAY 刷新 demux并复制下一帧所需压缩 fragment；耗时像素工作 MUST 在锁外完成，使前台 `reserve/commit` 不被后台整帧 decode阻塞。
- App presentation MUST NOT 直接创建 `HttpClient`/`HttpURLConnection`或直接消费 source transport。Venera `Network.*` 的 source runtime仍拥有Cookie、manual redirect、`cache-time`、`prevent-parallel`、requestId grouping与single-JS-invocation语义，但实际HTTP MUST由isolated plugin Dart process的reusable rhttp/reqwest resolver client执行；Kotlin/WebView bridge MUST NOT再持有第二HTTP client/connection pool。最终 media replay继续使用主流程rhttp direct transport；进程隔离允许两个owner-local client实例，但两者 MUST属于同一rhttp client family。
- host replay MUST 只用于可无状态平铺的单次 source request。遇到 redirect、`Set-Cookie`、未知 client wrapper、认证/session语义或成功 HTTP却非编码媒体响应时 MUST 切回 source-owned client；不得让独立 Dart HTTP client接管来源 Cookie/session状态。
- metadata/artwork MUST 经过 `ResourceCacheManager`；只有 Reader/章节 page body 与 artifact/download路径 MAY 通过明确命名的 page-body API绕过 response cache。插件仓库/APK/JS下载属于 control-plane，不得伪装成漫画 source response cache。 `CachedBrowsableComicSource` MUST NOT 暴露 artwork 加载 facade。`loadPageBytes` 与 streaming page loader MUST 共享同一 source-resolved response path；full-byte fallback MUST NOT 直接调用 raw source transport。章节下载的可变资源能力 MUST 作为单一 `ChapterResourceAccess` 原子绑定，不得使用多个 setter 形成半更新状态。
- 外部 artwork MUST 通过 source-confirmed canonical comic identity 查询统一 response cache；
  命中时不得解析来源、创建 source transport 或等待插件 activation。cache miss 才可进入
  source loader。raw Mihon/插件 locator只用于 runtime调用与章节身份，不得切分 durable artwork namespace。
- Home/阅读历史中已经持久化的 HTTP(S) artwork locator MUST 始终先进入统一 `ComicSourceResourceGateway` 的 source-independent durable-cache probe；active source/plugin 暂不可用时不得把网络 URL 交给本地文件 loader。durable miss 后才可要求来源 adapter。
- 已挂载 Home 的 chapter/SavedComic mutation MUST 通过 `HomeLibrarySession` write-through投影边界完成：durable store写入成功后同一次操作必须更新 session可见投影；不得先直接写 store再依赖详情页退出或 `_reloadLibrary()` 追平。Reader route最终 progress MUST 为 route-local状态，返回后只发布一次；不得用跨 route全局 latest-progress槽。
- Home library reload MUST NOT 用 mutation 之前捕获的旧 entries/SavedComic snapshot覆盖更新后的 write-through chapter/saved/progress投影。
- Comic artwork基础 cache schema revision MUST 只有一个 owner。External artwork由 `ComicSourceResourceGateway` 自动添加 `comicArtworkCacheSchemaRevision`；调用方 MAY 只提供 content-specific revision，MUST NOT 再传基础 schema revision形成并行 namespace。
- 初次 external runtime activation 在 session建立前发生 Binder `runtime-service-died/disconnected` 时，generation continuity MUST 由 Android runtime-service client拥有；最多跨一个 service generation。Dart/plugin activation层 MUST NOT 通过再次调用 activation实现同一恢复，业务/ABI/请求错误 MUST NOT 被重放。
- 来源确认过的同源 canonical comic identity SHOULD 持久化在 SavedComic 元数据中，供
  插件未激活时的书架只读归并使用；原始 comic/chapter request identity MUST 保持不变。
- 未访问的首页、书架、来源和杂项导航页 MUST 延迟构建；首次访问后页面状态 MAY 保留，
  但隐藏页面不得为首屏预先创建封面 loader 或重复发起 cover request。
- Home primary、enrichment 和可选 runtime 的状态仍 MUST 由各自 owner 管理；不得
  新增 App 私有正文/图片缓存或让 UI 直接调度网络。
- “更新漫画” MUST 只显示当前已在书架且存在 source-confirmed update 的漫画。章节/目录变化 MUST 由 `SavedComicRecord.sourceUpdateAt` 表示；confirmed同源 successor/version MUST 由 `ComicVersionRelationStore` 的持久 relation及其首次 `discoveredAt` 表示，并由 `HomeLibrarySession` 投影供 Home/source browser 同步消费。版本 relation MUST NOT 通过写 `sourceUpdateAt` 来伪装成章节更新。presentation MUST 合并两个事实源排序；阅读进度、普通 metadata刷新、仅浏览/阅读记录 MUST NOT 推进它们。漫画源卡片 MAY 将 confirmed successor 投影为右上更新感叹号，点击时 MUST 可直接查看该 raw version；该提示不得把 successor伪装成已入书架。远程漫画缺少偏好记录时 MUST NOT 默认视为已加入书架；阅读历史 MUST 单独按 `ReadingProgress.updatedAt` 排序。

### 1.2 详情页与来源迁移

- 详情页顶部控制栏 MUST 不重复显示漫画标题；漫画标题只在详情内容区显示。
- 存在阅读进度时，详情页 MUST 提供可操作的“继续”药丸按钮；继续/阅读历史行 MUST 位于
  章节总数行上方，阅读历史 MUST 与按钮位于同一行并放在按钮之后，历史文字之前显示时钟图标。继续 MUST 通过既有
  `onOpenChapter` facade 打开保存的章节，不得等待无关的来源刷新。

## 2. Reader 行为

### 2.1 Current 与输出连续性

- current MUST 具有最高 download、decode 和 upload 优先级。
- near/far 工作不得阻塞 current；current 的 holder/播放状态也不得冻结目标页网络。
- verified-equivalent physical alias MUST只共享physical artifact/writer/retry状态；当前consumer选择source transport后，实际full/range/resume request MUST使用该consumer的exact `DownloadId.canonicalUri`，MUST NOT把physical anchor URI泄漏到另一个版本consumer的transport。
- acquire-time verified physical alias的Reader网络进度 MUST直接投影resolved physical `DownloadSession`的`networkStartLength/committedLength/totalLength`；Pipeline MUST NOT按logical exact `DownloadId`建立第二份authoritative progress session表，Reader MUST只消费只读进度projection。
- 已有 output 在 replacement 前 MUST 保持可见；缺少动画 successor 时保持当前帧并等待 producer。
- loading MUST 绑定到具体媒体区域，不得用全局 overlay 隐藏已有页面。

### 2.2 翻页

- stable ownership midpoint 默认为 50%。
- 横向目标页覆盖率达到 0.15，纵向目标页真实进入视口时，MUST 建立 transition demand。纵向 `targetCoverage` MUST 只来自真实可见的非 current page；只有 current 可见时 MUST 为 null，MUST NOT 从 `logicalPosition` 的 page-local fraction 通过 floor/ceil 虚构隐藏 target。仍在 viewport 内的 outgoing page MAY 继续作为 transition，直到其真实离屏。
- current 浅水位 bootstrap MUST 优先：动态 current holder depth < 3 时，speculative next/next2/previous 不得启动新的 decode refill；静态 current 一帧即满足。若 current 暂时在等待 source，真实已进入 viewport 的 transition MAY 独立取得一帧，避免拖动目标黑屏。
- current bootstrap 建立后才恢复 next/next2/previous staged refill；transition 不得用深水位抢占 current 的基础播放水位。
- midpoint 后新 stable page MUST 成为 current；旧 current 的已上传 output MAY 作为独立 retained/last presentation 保留并暂停播放，但该 retention MUST NOT占用或跳过相对 previous/next slot。相邻旧 current仍 MUST按 offset -1/+1参与 encoded/decode window；大跳后若已离开7/3窗口则 retention不得单独制造 download/decode demand。
- 交接不得产生 targetless demand gap、黑屏或重新创建同一 identity。

### 2.3 连续模式与控制

- 内容 MUST 等比呈现，统一使用 `height / width`；不得裁切正文，或用负位移、重叠和多套比例公式掩盖接缝。
- Reader MUST 支持沉浸、跳页、暂停、倍速、方向和布局命令；命令只通过 Reader facade 提交。
- Reader slider MUST实时跟随拖动跳页：`onChanged`更新UI preview并通过Reader-owned scrub navigation推进PageView/current page；不得等到`onChangeEnd`才改变可见页。scrub observation MUST显式标记`Interaction.scrubbing`，其Pipeline计划只能包含当前页foreground download/decode/upload，不得逐格展开7/3 prefetch窗口；`onChangeEnd` MUST在最终页结束scrub并恢复正常完整窗口。viewport acknowledge前slider仍以preview/requested page作为受控显示值，不得被旧`currentIndex`回拉。
- Reader 页码或阅读模式改变后 MUST 通过既有 progress facade 持久化 `ReadingProgress`；App
  lifecycle 进入 inactive/paused/detached 和 Reader route dispose 时 MUST 强制 flush 最近进度。
  Home projection MUST 在写入成功后立即更新，不能要求先退出详情页才反映阅读历史。
- Reader 正常返回前 MUST 等待最终 progress writer drain；详情页等待 Reader route返回后 MUST 立即重读本地 snapshot。异常进程终止只能依靠持续 checkpoint降低损失窗口，不得宣称绝对 crash-safe。
- UI 控件存在性 MUST 来自 capability，不得用静态/动画猜测下载或播放能力。

## 3. Pipeline 与角色合同

`ReaderObs` MUST 表达 stable page、fractional position、current/target coverage、viewport/physical target、阅读方向、interaction/zoom 和单调 revision。

默认资源策略：

- encoded逻辑/retention与network-demand window：前 7 / 后 3；animated/未决WebP MUST同样保留完整3/7 demand。opaque plugin URI在manifest无WebP hint时，runtime ingress sniff到`ContentKind.webp` MAY作为transport-cost evidence启用既有bounded body flow，MUST NOT冒充animation truth。动画 MAY附加physical-task frame credit：current/可见transition unlimited，next/next2/previous默认5/3/2，其余远端默认1，decode staged waterline MAY把对应外层credit提高到2。ANMF structural count与DecodeSession-owned playable-prefix floor必须同时满足才 MAY park。dev.268起 flow/demand park MUST保留同一ByteResponse/StreamIterator与physical task；DownloadJob只释放NetLane body-read permit，不得通过`DownloadFlowSuspended`、`iterator.cancel()`、Range capability或Reader角色把“水位满足”解释成response结束。NetLane normal5 + current reserved1 MUST分别约束network/source transport lease与body-read permit；live source response park只释放body permit，MUST继续占transport lease，因此`running`可因local artifact/non-network physical work高于5，但live source/socket不得无界增长。不得存在独立`maxInactiveParkedResponses`容量owner；normal demanded work只有在transport lease饱和时 MAY回收`demanded=false` inactive parked lease，并 MUST以`downloadEvicted(evictionReason=inactive-transport-lease-reclaim)`独立记录，MUST NOT伪装成`downloadPreempted`或占用priority/body-read preemption transaction。retention eviction即使正在等待旧response退出，也 MUST NOT阻塞current-ranked handoff；current live-response reacquire MUST先于对另一blocked high-priority pending task发起新的destructive admission preemption。Reader profile MUST NOT按3/7推导socket容量。artifact-cache durable local body同时释放network transport lease与body-read permit；`consumerPacing`不保证native upstream byte backpressure，因此 live source response MUST由transport lease有界；不得恢复100ms pseudo-drain。任一resume/probe/full-body attempt在启动时authoritative partial边界前 MUST绕过frame credit。physical structural frame proof MUST由DownloadSession generation owner保存；真实eviction后若positive target已由partial+playable floor满足则不得无意义重开，target0/current或更高target才继续网络。static/non-WebP、artifact-cache/resident仍不得被WebP frame credit阻塞；
- 深度 decode 角色：前 2 / 后 1；
- 动态 holder 最大水位为 current/next/next2/previous：7 / 5 / 3 / 2；
- upload primary：current、transition；上一 current可通过独立 retained-output overlay获得 `last` upload demand，且不得改变其相对 download/decode role；
- lane normal concurrency：network 5、decode 3、upload 2；network/decode/upload 各 MUST 保留 1 个仅 current(priority 1000) 可用的 bounded handoff slot，transition(priority 900)不得占用；
- source bucket：local 2、remote 5。

Policy MUST 只输出 demand/keep，不得创建 transport、artifact、cursor 或 texture。静态一帧满足；静态证据 MUST NOT 把 near/far encoded-only 页面提升为 speculative decode/upload，非可见静态预热只能发生在 current/transition/next/next2/previous 稳定 decode 角色内。真实 viewport 可见静态页 MAY 获得一帧输出，且不得重新引入 `PageRole.visible`。纵排 dragging/scrolling/settling 期间，任何非 current/transition 且不在真实 viewport 的 speculative static page MUST defer UploadDemand，即使其稳定role为 immediate next/next2/previous；其 DecodeDemand MUST保持既有窗口语义，idle后 MAY恢复stable-role static warming。

## 4. 网络调度

- composition-owned `NetLane` MUST 是页面网络的唯一调度权威。
- current SHOULD 使用 priority 1000；network/decode/upload可各有一个current-only bounded handoff。network `NetLane`在normal 5槽满时 MUST先用唯一reserved槽直接admit current，MUST NOT仅为借该槽先取消running task；只有normal+reserved均饱和且current仍blocked时 MAY按统一effective rank与40分margin preempt。priority 780/800/820/900的normal work MUST NOT主动取消仍有consumer demand的active task来抢普通槽；只有`demanded=false`的already-admitted inactive task MAY在真实容量阻塞时由NetLane统一reclaim。破坏性network preemption MUST具有NetLane-owned incoming candidate stability：Reader当前100ms；candidate未连续保持high-priority blocked至窗口结束前 MUST NOT cancel active victim，但free/reserved slot admission MUST仍立即发生。每个NetLane MUST最多允许一个scheduler-preemption victim处于cancelled但尚未物理退出状态；该victim退出前其他blocked current MUST只排队/更新rank，不得继续cancel更多active transport。scheduler/consumer typed cancellation MUST只结束transport attempt；若writer已有authoritative bytes，DownloadJob MUST先flush再pause，DownloadSession MUST回`idle/failure=null`并保持committedLength/Ingress/epoch，MUST NOT写成`DownloadState.failed / Failure(cancelled)`。already-admitted task在logical claim归零后 MUST迁移rank0而不是由Reader/session直接cancel；queued且从未admit的undemanded work MAY直接移除。普通可Range-resume的committed partial不得仅因字节较多自动变成不可抢占sunk cost；victim经济性仍由统一`NetPolicyRank`的真实不可恢复restart cost决定。consumer-bound transport真实dispose、任务错误、显式用户取消仍可硬终止。
- DownloadJob、Reader、UploadSession 和 holder 不得建立第二套网络资格门控。
- 目标页 receiving transport 不得因 current holder depth、播放 underflow 或页面控件状态被暂停。
- 不得缩小**逻辑/retention 7/3或DownloadDemand 7/3**、关闭预下载或降低播放速度掩盖 identity、重复请求或 producer wake 缺陷；动画WebP只能在同一physical task内用frame credit与typed flow-control capability控制远端body流量，不能恢复2/4 eligibility、whole-body估算budget或cancel/reopen式流控。

## 5. 下载、partial 与 artifact

- 下载管理 Presentation MUST 先由 Home 已有 download/whole-queue projection构造首帧；durable artifact/cache全量检查 MUST 在 route首帧之后异步刷新，并优先使用 bulk inspection，不得以逐章节扫描阻塞 Navigator route首次绘制。
- GET/HEAD MUST 零 body且不得携带仅适用于实体 body 的 headers。
- 同一 DownloadId MUST 只有一个 active writer；partial MUST 是连续前缀并可恢复。对同一稳定 DownloadId，已经提交并成为 playback authority 的 `committedLength` MUST 单调不减；transport restart、missing validators、Range rejection、retry 或 source-open fallback MUST NOT 删除、截短、换 epoch 或重建仍与 artifact 一致的内存 Ingress。同一actual request URI的strong validator可直接Range resume；validator缺失或仅存在其他provider URI的validator且旧 total length已知时，DownloadJob SHOULD先用最多64 KiB尾部 overlap Range验证continuity，并且只有精确206、精确range start、total length一致和overlap逐字节一致时才可从旧 boundary继续append。若服务器忽略Range并以200返回完整body，MUST复用该同一response进入full-prefix catch-up，不得因probe失败再次打开第二条full response；probe不可用时才MAY直接从byte 0 catch-up。full-body continuation MUST使用bounded cost admission：partial<1MiB不得因成本门槛阻止；1MiB<=partial<8MiB时priority>=820才可继续；partial>=8MiB时priority>=900才可继续。defer MUST立即释放当前response并保持artifact/Ingress/epoch不变。Range probe本身仍MAY执行。coordinator MUST以DownloadId+当前committedLength记忆defer，低priority demand detach/re-add在partial未变化时不得重新联网；committedLength变化或priority达到对应门槛时 MUST清除defer并重新probe。该记忆不得持久化为endpoint Range能力，也 MUST NOT读取endpoint hash、`duplicatePrefixBytes`或decode/playback诊断作为admission输入。 已经开始的不可恢复full-body attempt MAY 将取消后必须重付的attempt wall time与response consumed bytes作为NetLane victim-retention成本事实；NetLane MUST以连续、单调、有上限的函数形成restart-cost retention：当前用5s时间尺度与4MiB流量尺度形成`costScore`，同时计算bounded +100与base→current-safe headroom两种投影，并固定取`1/3 bounded + 2/3 headroom`。logical detach把base降为0后 MAY保留成本保护，但 MUST NOT仅凭历史投入占满整个base→current-safe剩余rank空间。该投影 MUST NOT提高task的admission/pending priority，且current=1000 MUST始终保持配置的preemption margin。普通可Range-resume的committed工作、endpoint hash、HTTP version或网速估计 MUST NOT直接产生该bonus。所有重复校验字节 MUST NOT写入artifact/Ingress；mismatch、取消或提前EOF MUST保留旧playable partial；其中typed `ErrorCode.cancelled`无论从DownloadJob还是其他generic fail closure进入，都 MUST机械转为writer pause而不是content failure，真实network/content/validator/artifact错误才 MAY进入failed。`resumeAccepted/resumeRestarted` MAY记录只读`resumeProbe*`与`duplicatePrefixBytes`诊断，但NetLane/Reader/retry/cache MUST NOT读取这些字段形成policy。只有明确owner/identity mismatch、artifact corruption或显式evict/清缓存 MAY使committed playback bytes减少。
- seal/promotion MUST 原子更新 metadata；cache clear 不得删除 active artifact。Artifact partial→final promotion的data-file rename与内存state切换之间不得向Reader泄漏人工0字节窗口：readBytes/readChunks/readPrefix MUST由Artifact owner在preferred path open失败时只fallback同一Artifact的alternate partial/final path，并以已打开file handle完成读取；Reader/sessions MUST NOT自行选择promotion path。
- `DownloadJob` MUST 是 page-body transport chunk aggregation的唯一owner：任意底层小块先形成首批约16KiB，之后按64KiB `sourceProgressQuantumBytes`提交session。production rhttp direct transport对rangeStart=0的完整/首段response MUST执行媒体前缀验证并保持raw streaming cadence；合法206且`Content-Range.start > 0`的中段 MUST跳过完整文件magic-prefix要求，MUST NOT仅因中段不含图片文件头而转runtime fallback。rhttp transport MUST NOT再次增加64/256KiB framing；底层packet边界也不得直接放大为数万次artifact/native append。scheduler cancellation MUST覆盖response完整生命周期；request已返回并开始stream后，consumer/task取消仍 MUST abort底层source/HTTP response。partial artifact append MUST NOT在UI isolate逐chunk执行checksum CPU循环；checksum MAY延迟到seal/restore边界计算，但seal/promotion前 MUST成为权威且通过expected checksum验证。 rhttp response 的HTTP version与匿名 remote-IP hash MAY作为每response一次的低开销诊断随`sourceRead`输出；高频receive-progress/raw-body diagnostics MAY在bridge边界记录event/gap/byte统计，但普通product/release MUST默认关闭`onReceiveProgress`注册，只有non-product或显式`ZIC_RHTTP_RECEIVE_PROGRESS_DIAGNOSTICS`诊断构建 MAY启用。所有这些字段 MUST observation-only，MUST NOT驱动NetLane、Reader、retry、cache或chunk framing；不得仅因current吞吐较低就新增第二个bandwidth scheduler。
- local 和 remote WebP decode-prefix hint SHOULD 分别使用 1 MiB 和 256 KiB quantum；该 hint 不等同于 transport chunk。
- 读取失败 MUST 保留可归因错误，不得表现为永久 loading。
- Home/书架漫画卡片的下载完成勾 MUST 由本次显式下载命令完成事件驱动，而不是由任意 durable chapter cache命中推导。单章节命令完成 MUST 使用与整本完成可区分的空心标记；整本下载仅在 whole-comic queue进入 complete后 MAY 显示绿色实心标记。完成标记 MUST 为临时 Presentation状态，并在进入该漫画详情时清除；durable离线事实继续属于 downloads/artifact。

## 6. Animated WebP

- 两个 Dart decode isolate MUST 在 App 运行期常驻；libwebp 帧内 MUST 单线程。
- 首次 decode SHOULD 优先单帧；current 后续 MAY 每次批量返回最多两帧。
- holder MUST 是 decoded successor 的权威所有者；可见 output 不得计入 successor depth。
- current bootstrap MUST 先建立静态1帧或动态最多3帧的浅水位；bootstrap 未满足时 speculative neighbor refill MUST 为0。current 等 source 时，真实 transition depth=0 MAY 独立取得1帧；bootstrap完成后恢复 staged current/neighbor refill。
- 不得恢复独立 startup-buffer 或以 playback timer/underflow 控制网络 eligibility；current bootstrap 只属于 decode refill policy，不创建第二套 Reader gate。
- metadata 未完成且 source 增长时 demux MUST 可刷新；未封缄 need-more-data MUST 等待 source revision，而不是定时销毁 cursor。
- source revision MUST 保持 pending，直到对应 DecodeSession 实际执行 fill，或其当前 snapshot 明确证明无需 fill；staged refill policy 因 current bootstrap 暂时返回空决策 MUST NOT 被解释为 source 已消费。角色晋升为 current 后 MUST 能从 projection 当前 revision/state 重新发现已就绪 source。 DecodeSession的generation authority MUST唯一来自当前Reader-local ingress projection；MUST NOT同时读取physical DownloadSession epoch进行第二份preflight。若projection epoch在异步decode期间变化，旧work MUST按生命周期cancel而非terminal decode failure；若projection在同epoch内rebuild并替换`EncodedSource`实例，DecodeSession MUST丢弃绑定旧实例的cursor/holder并从当前source重新创建cursor。LiveCoordinator MUST NOT把返回`failed/failure`的DecodeSnapshot记为已消费source revision。 Reader ingress registry的`get(session)` MUST区分physical object generation与Reader encoded generation：same DownloadId的新physical session仍属于新的physical object generation；unfinished/failed或仍有pending synchronized attachment的same DownloadId新physical session MUST创建fresh Reader-local projection/source；若existing projection已经sealed、sourceReady、无failure且无pending attachment，则same exact DownloadId的transient DownloadSession recreation MAY保留同一immutable Reader encoded generation，并 MUST NOT因此invalidate decode/upload。旧same-id physical teardown MUST做concrete session identity校验。synchronized late join MUST在加入physical live fan-out前同时证明physical boundary稳定且projection snapshot的epoch/length/sealed/failure精确闭合，MUST NOT仅因physical revision未变就宣称incomplete projection已attached。UploadSession在physical-generation invalidation触发的dispose MUST立即退休当前uploader slot并清除deferred-release请求；旧generation pending prepare随后结束 MUST NOT再次按logical DecodeId release replacement generation。普通demand detach的pending-upload release语义保持不变。 UploadRegistry MUST把logical DecodeId与concrete DecodeSession generation区分：`get/prepare`命中既有UploadSession时 MUST验证`identical(existing.decode, decodes.get(id))`；不一致时 MUST先dispose旧UploadSession再创建replacement，MUST NOT把旧holder为空解释为当前DecodeRegistry仍无frame，也MUST NOT让UploadSession在生命周期中动态切换DecodeSession。
- native target canvas MUST 生成预乘 RGBA；Android/Flutter fallback 不得再次预乘。
- finite animation 到 EOF MUST 保留最后一帧；静态零时长帧不得启动 playback timer。

## 7. Upload 与 Android texture

- replacement 前旧 frame MUST 保持有效；release MUST 等待最后一个 frame owner。
- Android MUST 使用一个串行 blit lane；`scheduleFrame()` 和 MethodChannel result 必须在 platform thread有序完成。
- platform queue、schedule queue/call、blit 和 channel dispatch MUST 分别计时。
- 已承载 output 的 texture/SurfaceProducer MUST 随 output 释放，不得跨 Reader 会话复用。
- 只有从未呈现过的 prewarm lease MAY 短期复用；App 非 resumed 时 SHOULD 清理 idle prewarm。

## 8. Reader 资源会话生命周期

- Reader Host MUST 通过 factory acquire/release 资源会话，不能在 Widget dispose 中直接销毁所有章节资源。
- 实现 MAY有界保留一个 idle 章节会话最多两分钟以复用Reader-local Source/Decode状态；physical Download状态 MAY由composition transfer runtime独立于该Reader retention继续持有，但不得因此保留已退出Reader的native ingress/transport provider。
- retention key MUST 使用稳定章节/source/loader revision，不得依赖临时 loader 对象 identity。
- retain 时 MUST 释放 Reader binding、page projection、playback wake、present claim和 used texture。
- TTL、key 变化、容量淘汰或 composition shutdown 时 MUST 完整逆序 dispose。
- retention 不得成为 Reader 私有正文缓存或 used texture cache。

## 9. Identity 与缓存

- 同一 request plan、DownloadSession、artifact 和 decode task MUST 按稳定 identity 合并；旧 epoch/revision 结果不得提交。
- 封面、详情、搜索和章节元数据 MUST 由统一 response cache 拥有，key 包含 namespace、稳定 identity 和必要 revision。
- Promoted Reader artifact MUST由唯一`ArtifactCacheManager`/persistent cache backend拥有；未promoted partial MUST与immutable cache分离。physical `DownloadSession`的`committedLength/residentCacheBacked`只声明transfer/residency状态，不得隐含session artifact一定保存同一正文；late Reader对resident immutable body的encoded-source replay MUST由Reader-local replay authority向唯一`ArtifactCacheManager`查询，或对可重开`file/content/asset` source读取严格有界prefix，且read quantum MUST继续经过composition artifact-read scheduler。hot partial与source/network task的owner MUST是应用级`CompositionDownloadTransferRuntime`，Reader、prefetch、chapter command与whole-comic不得创建第二套physical registry/job；它们只能以scoped `TransferDemand`/aggregation表达需求。priority MUST只决定竞争顺序，不能替代completion语义；显式durable download的required-completion claim MUST允许在获得执行槽后完成costly full-body catch-up。logical consumer/claim退出 MUST只改变调度需求，不得从sessions层触发durable partial I/O；hot physical prefix在独立hot partial预算受压或runtime最终dispose时仍由downloads层`PartialDownloadHandoff`持久化后退休；App进入paused/detached时composition owner SHOULD对当前committed hot partial做durable safety checkpoint，但 checkpoint MUST NOT退休hot owner或改变session generation。cold-store失败 MUST保留hot owner。sessions层的retire primitive MUST只处理claim/task/session/alias机械生命周期，不得依赖durable store或retention budget。promoted artifact完成反馈必须等待唯一durable store handoff可读；同一promoted immutable session的自动handoff成功后 MUST对后续snapshot/demand churn幂等，但显式required exact barrier MUST重新验证目标durable。跨版本equivalence在新exact identity尚无session且direct verified proof命中一个或多个可复用既有physical owner时 MAY在acquire前绑定到其中一个；multiple owners MUST以稳定authority排序择优复用而不得创建第三owner，已存在session之间仍 MUST保持分离，source-resident非cache body MUST保持exact。 physical session MUST only be resume/admission或Download ownership输入。 对unsealed WebP且尚无成功frame的decode exception MAY转为有界prefix-growth wait；sealed source或已有成功frame后的decode exception MUST保持authoritative failure。
- 页面热字节 MUST 有界；默认可为 10 项/256 MiB。App/Reader 不得创建第二套图片 byte LRU。
- artifact reuse MUST 有 checksum、来源 page key、内容 hash 或用户确认/来源确认关系上的强对应证据；标题、URL token 或相同页码不足以证明等价。已确认同源版本 MAY 在不迁移实体的情况下注册有界 verified-equivalence：opaque locator必须先经既有 source request-plan owner解析，首/中/末强媒体identity证明稳定offset并持久化mapping；mapping验证时间 MUST 以严格 String timestamp解码，非法类型/时间必须拒绝。source版本发现 MAY 每次入口异步刷新，但最近已验证且仍在有界freshness窗口内的mapping SHOULD跳过重复page-identity验证。equivalence MUST 是lookup fallback而非storage redirect：请求自己的exact DownloadId先查，miss后才查直接确认相关版本；登记时不要求source artifact已存在，因此迟到promote MAY被后续demand复用。ArtifactCacheManager MUST NOT持有directed hard alias/rekey；equivalence不得改变exact写入identity、不得复制字节或移动durable library state。普通Reader promotion若direct verified-equivalent durable artifact已存在且长度一致 SHOULD复用该artifact而不materialize第二份exact durable body；只有显式required-completion语义 MAY要求exact durable materialization。相关版本full artifact迟到promote时，已独立存在的physical session MUST保持原owner与当前claim语义；后续新的exact demand仍可在acquire时依据direct verified proof加入已有physical authority。显式迁移 MUST只登记verified equivalence proof，不得恢复hard alias/rekey。

- 纵向 Reader 的媒体 Presentation MUST与item-extent owner解耦：`ReaderVerticalGeometry` MAY决定page box与anchor，但已知source dimensions的`fitWidth`媒体 MUST独立保持source aspect，MUST NOT仅因父sliver box被假定精确就退化成无界`BoxFit.fill`拉伸；active-scroll真实/暂态box不匹配只能裁切/留白，不得改变媒体比例。 Reader item extent与`MediaAspectViewport`的最终aspect authority MUST同源于physical source canvas；`PipelinePageStreamSnapshot` MUST只读投影`sourceCanvasWidth/sourceCanvasHeight`并由`LocalImagePlayer`优先采用。output/surface decoded raster MAY作为pixel carrier与provisional local尺寸，但MUST NOT在sourceCanvas已知后覆盖presentation aspect。dev.297的`<=0.5 physical pixel` bounded fill与external-texture paint snap已被设备幅度证据否证并MUST保持回滚；Presentation MUST继续aspect-preserving fit。UploadDemand MUST只表示新的upload/present调度资格，MUST NOT清空一个已成功authoritative static UI projection。directional decode previous1/next2 policy仍是唯一decode work窗口；但对已经存在的authoritative static surface，Presentation MAY在该directional policy两个可能方向的并集`current±2`内跨direction flip造成的decode-plan gap保留surface/PresentClaim。该continuity envelope MUST只保留既有projection，MUST NOT创建DecodeDemand/UploadDemand/decode session或调用present，也不得改变2/1 decode policy；超出±2、decode target/generation/identity变化、真实output/upload dispose或最后listener移除时 MUST释放。animated output MUST NOT通过该例外跨upload-demand gap保留。
- 纵向 Reader 的异步 `pageAspectRatios` 更新 MUST NOT在dragging/scrolling/settling/scrubbing期间改变真实visible tail及之前的 `ReaderVerticalGeometry` / `itemExtentBuilder`；一次连续用户滚动 MUST保持当前viewport prefix稳定。DecodeSession已成功decode的frame可触发Pipeline提前解析尺寸，但`PipelinePageDimensionsFeed`的最终geometry fact MUST区分`sourceCanvas`与`decodedRaster`：source canvas优先，decoded raster仅provisional且不得覆盖source；dimension event MUST携带稳定`pageIndex/assetKey/width/height/basis`并由ReaderRuntime现有ratio owner消费。`LocalImagePlayer`从output surface取得的non-authoritative raster尺寸不得通过`onDimensionsChanged`进入Reader geometry，也不得覆盖已由page-stream physical sourceCanvas确立的presentation aspect。`PipelinePageOutputStream`与`PipelineTransferProgressPublisher` MUST通过`PipelineFrameScheduler`消费frame boundary，MUST NOT直接访问Flutter binding；Reader transfer presentation MUST订阅`PipelineTransferProgressFeed`而非Pipeline-owned`ValueNotifier`。严格位于真实visible tail之后的future page source ratio MAY在active scroll中提前进入layout snapshot，因为其extent不得改变当前pixels对应prefix；visible tail及之前的新ratio只允许latest-wins暂存，真正idle后 MAY一次提交，并且只允许以提交前top-pixel anchor补偿这一次真实extent变化；MUST NOT恢复dev.207 ratio-driven `jumpTo`循环，也 MUST NOT恢复dev.286 `presentationExtentAt`/OverflowBox裁切workaround。真实viewport/DPR/stitch变化与显式navigation仍 MAY保留/恢复anchor。
- 纵向 page-host composition retention MUST 与Pipeline资源窗口分离；production仅保留nominal `current±7` AutomaticKeepAlive。不得恢复已被dev.285设备证据否证并回滚的dev.284 mount-travel keepAlive guard，也不得用扩大`cacheExtent`替代真实布局/资源根因分析。

## 10. 插件与来源

- 插件 MUST 在隔离、信任和权限门禁内执行，只返回 catalog 数据、request plan 或显式有界 transform 结果。
- 普通图片正文 SHOULD 由宿主 transport 流式下载。平台 transport MAY 将底层网络小包聚合为面向 Pipeline 的较大逻辑块，以降低 Dart 调度/commit 开销；首播块 SHOULD 小于持续传输块，聚合不得改变字节顺序、取消、Range/validator、artifact或重试所有权。
- 插件不得访问导航、Reader、demand、artifact、App state 或底层缓存。
- Cookie、token、脚本 payload 和 Base64 正文不得原样写入 Trace。

## 11. Telemetry

Trace MUST 记录 demand/session/writer/source/decode/upload/present/retry/lifecycle 的可归因摘要。composition physical transfer对同一共享App/export TraceSink的同一事件 MUST 只投递一次；Reader-local memory trace MAY分别保留该physical event，但多个Reader不得放大全局导出次数。前若干不同帧 SHOULD 保留逐帧 timing，至少区分 lane queue、source wait、cursor/worker/native decode、upload backpressure、output prepare、platform/schedule queue、blit/replace和 channel dispatch。 纵排抖动诊断 MAY 以有界低频`pageLayoutSnapshot`记录真实可见page RenderBox的expected extent、constraints/size、paint/global rect、transform、role与interaction；post-frame RenderBox若与scroll position做残差比较，MUST使用同一post-frame时点的live scroll pixels，不得混用调度采样时的旧pixels制造伪layout residual。该事件 MUST 只用于归因，MUST NOT 成为layout、navigation、presentation或scheduler输入。 纵排Reader MAY记录真实Flutter `readerFrameTiming`（build/raster/total span、vsync interval）以诊断整帧cadence；Flutter timing callback可批量返回历史frames，因此Reader MUST NOT把callback时刻的scroll/current/interaction伪装成每个历史frame的逐帧上下文，SHOULD记录batch index/size、callback monotonic与last-vsync anchor供时间轴重建。Flutter `SchedulerBinding`/`dart:ui FrameTiming`/`FramePhase` MUST由`reader_runtime` presentation adapter归一化成框架无关`ReaderFrameTimingSample`后再交给Reader，`ReaderView` MUST NOT直接解析engine timing API；该事件同样只用于归因，MUST NOT驱动任何Reader/Pipeline状态。

identity 超限时使用稳定 hash 与原长度；高频事件 MAY 在导出投影按语义分桶合并。`framePipelineTiming` 的合并 MUST 至少区分 trace reason、dominant stage 与角色，`decodeRefill` 的合并 MUST 至少区分 role、stage 与 source-wake，并保留 first/last、coalesced count 以及关键 timing/source length/revision 的 min/max；错误和生命周期边缘、retry/resume、`sourceRead` 与网络任务边缘 MUST 保留。Trace 不得成为业务状态权威来源，导出压缩 MUST NOT 驱动调度、重试或缓存，overlapping total 不得与子阶段重复参与 dominant 归因。

## 12. 测试与发布

- owner test MUST 位于实现所属 package；App 测试不得导入低层 `src/` 或重复低层算法。
- 异步测试 MUST 使用可控 Future、状态对象或稳定 key，不得固定 pump 猜测完成。
- quarantine MUST 有稳定 ID、原因、仍运行的 owner 覆盖和解除条件。

发布候选 MUST 尽可能完成 analyzer、受影响 package/App tests、native tests、Android debug/release、Mihon/Venera/Android 合同、干净 ZIP 独立复验，并排除 `.git`、`.dart_tool`、`build`、`.gradle`、`.deps`、`target`、`__pycache__`、`.pyc`、`.class`、`.rej` 和 `.orig`。未执行项 MUST 在 Status/audit 标为 Unverified。

## Artwork 与插件会话稳定性要求

1. 失败封面不得因父组件 rebuild、App resume、timer/watchdog或第二个 ImageStream自动重新发起请求；Presentation MUST 保持稳定占位，只有显式来源刷新、资源 revision或稳定 identity变化才允许重新加载。
2. 实际预览行含横图时 MUST 最多 2 项，纯竖图行 MUST 最多 3 项；为满足该规则 MAY 在相邻三个候选内做一次最小局部重排，并受用户设置的更小上限约束；不得用额外间隔消耗剩余宽度。
3. 详情与漫画源下拉刷新 MUST 共用同一个组件拥有 edge trigger、位移、刷新进度和成功/失败反馈；结果图标 MUST 与刷新指示器使用同一落点。

4. encoded artwork source 已就绪后，普通 artwork MUST 只创建一个 ImageProvider/解码监听；需要裁剪或尺寸测量的 Presentation MAY 显式监听一个 ImageStream并直接绘制 decoded image，但 MUST NOT 同时构建第二个 `Image`监听同一 provider。
5. 远程详情 MUST 先显示已有 catalog cache，并等待当前 active source adapter 完成后台刷新；预览、评论及章节操作 MUST 在调用时解析当前 adapter，不得持有插件重启前的关闭 session。
6. Mihon chapter catalog MUST 只投影插件/source API实际返回的完整 `SChapter` 列表。TachiyomiX 1.6/current Mihon MUST 先调用 `getMangaUpdate(manga, existingChapters, ..., fetchChapters=true)`；只有 combined能力明确不存在时 MAY回退 legacy `fetchMangaDetails/fetchChapterList`。正文 MUST先调用 `getPageList(SChapter)`，只有能力不存在时 MAY回退 `fetchPageList`。成功空列表是合法结果；真实调用错误保持失败。MUST NOT 从 manga URL生成兼容单章，也不得按标题、`SChapter.url`、number或sequence推断、增加、删除或合并章节。
7. Reader progress 的有序性与 durable I/O MUST 解耦：SQLite实现 MUST 在非 UI isolate执行同步 sqlite3/章节校验；Reader页面变化只入队 latest checkpoint，不得逐页发布 Home/library projection。Reader route MUST NOT 等待 durable barrier；返回后 Home/详情只发布最终内存 progress投影，storage isolate按自身 batch/生命周期策略完成持久化。
8. 外部 artwork MUST 统一通过 `ComicSourceResourceGateway`；raw plugin comic locator 与 durable artwork identity MUST 分离。Mihon 等可变 raw locator必须使用 source canonical comic identity构造封面/预览 cache namespace；`mihon:resource:` 等插件 URI不得传给本地文件 loader。
9. 同一 browser snapshot revision MUST NOT 在每个 HTTP 请求前重复覆盖 runtime Cookie；新 revision可再次导入。Mihon首个重试 MUST能从 snapshot同步获得 cookie，不得依赖 Android `CookieManager.setCookie()` 的异步持久化时序。
10. retryable runtime lifecycle envelope MAY 自动重新激活并重试一次；业务错误和 `source-verification-required` MUST NOT 被当作 runtime崩溃吞掉。
11. Mihon/外部插件同 pluginId 的 runtime restart或更新 MUST 使用事务式 replacement：候选 session先完成 activation、source identity/ABI等验证，成功后才能替换当前 source owner并关闭旧 session；候选失败 MUST 保留旧 session。不得先 deactivate再尝试 activate。
12. Mihon `imageRequest(page)`（或等价 source request）的 URL、method、headers与必要 request body MUST 原样进入 `ComicResourceRequest`；GET/HEAD body MUST 为 null。宿主直连 MAY补 source OkHttp CookieJar的当前 Cookie与 browser-session UA，但不得把普通图片完整 body路由回插件 JSON/Base64 RPC。

- 同源版本媒体复用 MUST 将强identity/offset验证放在非阻塞后台并持久化chapter mapping；Reader route前 MAY读取本地mapping并登记verified-equivalence fallback，但 MUST NOT等待source request-plan或网络解析。后台mapping完成后 SHOULD立即登记等价页，使当前仍存活Reader的后续未启动demand也能看到相关版本之后才promote的immutable artifact。source-card版本提醒 MUST区分relation predecessor与successor的raw/canonical identity。partial只允许复用已持久化、inactive且mapping已验证的前缀；版本warmup/Reader入口 MUST NOT预先复制cross-version partial到目标exact key。physical prepare MUST exact-first，exact miss时 MAY从direct verified equivalents中选择可用cold partial并直接恢复，SHOULD选择最长可用prefix；跨版本ETag/Last-Modified MUST丢弃，续传仍 MUST通过validatorless overlap字节验证。durable partial lookup MUST保持在异步physical prepare边界，MUST NOT把存储I/O塞入同步Reader demand planning；durable partial existence/read MUST由persistent index/file authority直接解析，hit/miss MUST NOT通过session registry `get()`或`DownloadSession.restore()` materialize synthetic durable-store session；只有durable mutation MAY使用store内部session/writer；该local prepare MUST在NetLane transport/source admission之前由physical owner single-flight执行，MUST NOT等待network lease才开始hydrate；local prepare完成顺序 MUST NOT定义network task创建顺序；完成后physical owner MUST按当前`DownloadSession.effectivePriority`保持local→network rank连续性，lower-priority ready work不得越过仍在prepare的higher-priority demanded work，随后才交给唯一NetLane；cold partial durable read MUST与artifact-cache replay共用composition `ArtifactCacheReadScheduler`并按chunk/dynamic priority调度，MUST NOT因3/7前移创建无界本地read并发或第二local scheduler。prepare期间的demand revision只更新claims，完成后 MUST重新解析当前preferred claim；若local prepare失败 SHOULD单次降级到provider path而不得形成cold-store retry loop。跨版本已经各自创建的independent hot physical session MUST保持各自单writer且不得事后merge；新exact identity在session创建前若有direct verified proof命中existing physical authority，则 MAY通过acquire-time alias共享一个既有hot physical transfer；若同时命中多个owner，MUST优先promoted，其次active writer/run、demanded、可恢复committed partial，并以committed length、demand/priority和稳定identity作确定性择优，MUST NOT因ambiguity创建新的第三physical session。
