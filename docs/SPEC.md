
# zic Product and Engineering Specification

本文件是规范，不是实施报告。`MUST` 表示发布合同，`SHOULD` 表示默认要求，`MAY` 表示可选行为。实现和验证状态见 `IMPLEMENTATION_STATUS.md`。`ARCHITECTURE.md` 描述当前代码如何实现本文件的合同（分层、所有权、机制与数据流），两文件分工不同、不互相复制条款。

## 1. 产品范围

zic MUST 支持 Android 上的本地/远程漫画、LTR/RTL/纵向阅读、静态图片、Animated WebP、partial/resume/offline artifact、漫画源浏览与受控插件扩展，以及本地 Debug Trace 导出。

项目不承诺 DRM 绕过、通用视频播放、社交功能或模型直接操作底层资源生命周期。

阅读引擎的几何、输出与资源调度合同见第 2、3 章；各合同的实现机制（分层、所有权与数据流）见 `ARCHITECTURE.md`。

### 1.1 首页冷启动

- bootstrap 与 durable service 之间 MUST 通过稳定 handoff 原地切换 `HomeLibrarySession` 的服务；不得因服务到达更换 `MaterialApp`/Home key 或销毁重建首页导航状态。快照已证明 revision 一致时 handoff MUST 保持现有更新漫画/阅读历史投影，不得重复发布同一 projection。

- Home MUST 在本地库的 cover-bearing primary 数据可用后先呈现首页；native media prewarm、持久整本队列 restore、外部插件 activation 和 enrichment 不得成为首封面请求的硬门槛。
- 启动 build MUST 不等待 durable services。入口 MUST 直接挂载不依赖 durable services 的 memory-backed Home，不得创建自定义 Flutter bootstrap surface；durable service open MUST 在首个 Home frame 之后立即异步启动，且不得决定 Home 是否可见。
- 空安装 MAY 在没有用户持久动作时保持 memory-backed Home 且不创建 core SQLite/WAL；首次显式章节下载或整本入队 MUST 在冲突探测、placement claim 和任何下载/队列写入前等待同一个 runtime-owned durable handoff，并原地采用 library、chapter composition、artifact cache 与 whole-comic queue。强制打开或 adoption 失败 MUST 终止该动作，不得让内存下载服务发布伪持久完成状态。
- 外观 MUST 读取并持久化 `ThemeMode`；AMOLED 开关启用时，且当前有效主题为深色，`darkTheme` 的 surface/scaffold/canvas 背景 MUST 使用纯黑。首帧加载背景 MUST 跟随有效主题，不得为启动阶段强制使用浅色。
- 首页根路由的系统返回 MUST 先显示“再按一次返回键退出”确认提示，并在确认窗口（当前为 2 秒）内再次返回才结束应用；窗口过期后 MUST 重新要求确认。该确认 MUST 只拦截根路由自身的返回，MUST NOT 改变其他路由（Reader、详情、对话框）或漫画源页内部返回手势的既有语义。
- Durable service open 完成后 MUST 主动提交内存 Home 到 durable projection；该提交不得只注册等待下一帧的回调而不安排 frame，否则用户手势不得成为加载更新漫画和阅读历史的隐式触发条件。
- 首帧前只允许建立轻量 startup/trace channel；native decode、`media_core` texture、rhttp 和 feature bridge MUST 在实际 Reader/source/platform capability 使用前保持未初始化或未挂载，首次使用只能由对应 capability 自己按需挂载。
- Android `FlutterEngine` MUST 关闭 embedding 的自动 `GeneratedPluginRegistrant` 注册；仅覆盖 `configureFlutterEngine` 不足以满足该边界，因为隐式 engine 会在该回调之前注册插件。feature bridge 只能在对应 capability 通过 startup channel 显式挂载。
- `LocalMediaBridge` 的 Android `pickImageDirectory`、`scanImageDirectory`、`openDocument` 与 `readDocument` MUST 在调用 `dev.zic/local_media` 前通过 startup channel single-flight attach `local_media_bridge`；这样持久记录直接恢复到 Reader 时不得依赖曾经执行过的文件夹选择流程。
- Android 应用存储根目录 MUST 优先随 Dart entrypoint args 同步注入，避免冷启动首次 MethodChannel 往返；旧宿主才由轻量 startup channel 返回，不能为了首个 `path_provider` 查询提前挂载 JNI。Home/runtime composition MUST 直接挂载到 Flutter root，不得通过自定义 bootstrap surface 或 deferred loading unit 延后首个可见 raster。首帧后的异步阶段只打开 durable/native/plugin capability，UI isolate 仍是唯一的 Flutter presentation/composition owner。
- 新安装且不存在 imported-library、offline-cache 或 whole-comic queue 状态时，Home MUST不打开 SQLite 或创建 WAL/schema；`LazyImportedLibraryStore` MUST 以内存投影服务，并在首次明确持久化写入时先将该投影迁移到 SQLite，再转发写入。已有 durable state 的服务只能在 Home 可见窗口之后打开。SQLite 句柄 MUST NOT 跨 isolate 传递。
- 已有 durable state 时，Home MAY 先读取 `HomeProjectionSnapshotStore` 的上一次成功投影，以 stale-while-revalidate 方式显示更新漫画和阅读历史；bootstrap/memory-backed HomeMUST NOT 将空投影写回快照。SQLite MUST 继续是唯一事实源，reconcile 后只替换新增、修改或删除的 identity，并异步原子写回新快照。快照 SHOULD 保存 SQLite Home projection revision；修订号一致时 MUST 允许直接复用快照，只有修订号变化或无法证明一致时才扫描事实源。快照 v2的 entries MUST 只包含 Home 元数据、pageCount、cover locator 与 progress，不得复制完整 pagelocator；旧 v1 读取成功后 MUST 自动原子重写为 v2。compact entry 在 Reader、下载或版本迁移前 MUST 通过 authoritative library hydrate 完整 pages。快照缺失、损坏、版本不兼容或读取失败 MUST 静默回退 SQLite，不能阻塞 Home 或覆盖 SQLite 数据。
- 快照序列化结果超过 64 KiB 时 SHOULD 使用 gzip，读取 MUST 同时兼容明文与 gzip；旧 v1 或大型明文快照读取成功后 MUST 自动原子重写为 v2 compact gzip。
- Whole-comic queue MUST 保持为独立队列状态文件，不得复制 Home entries 或章节正文；恢复 SHOULD 通过章节下载索引的 `inspectMany()` 批量投影，并在 Home primary 可见后后台完成，queue `ready` 不得成为更新漫画或阅读历史首显的硬门槛。
- 空的或从未产生阅读记录的 imported library 打开 MUST NOT 创建 Reader progress writer或第二个 SQLite/WAL 连接；该 writer 只能在首次真正写入 `ReadingProgress` 时懒启动，且不能反向成为 Home 冷启动的硬门槛。
- Home 启动期缺失的来源/漫画默认偏好 MUST 先以内存投影提供给首个 Home；不得为建立这些默认值在 UI isolate 同步执行 SQLite 写入。只有用户明确修改偏好时才 MUST 持久化该偏好，之后的 reload MUST 继续尊重已存储值。
- 首次安装缺失的 `app_preferences.json` MUST 先使用内存默认偏好；启动阶段不得为写出完整默认文档执行 flush/rename。用户首次修改任一应用偏好时才创建并持久化该文档。
- 外部来源可以在首帧之后 ready；封面 presentation MUST 使用稳定 canonical artwork identity。cache miss 在等待中的外部 source 首次发布前 MUST 保持同一个资源请求 pending，不能先以 source-unavailable 失败；source readiness 完成后仍不可用、transport 或 decode 失败时 MUST 保持稳定占位，不得由定时器、App resume、first-frame watchdog、provider eviction 或 loader closure 变化自动重启请求；只有显式来源刷新、资源 revision 或稳定 identity变化才能重新加载。
- Home 启动 MUST NOT 枚举 Android 上全部已安装包来发现 Mihon 扩展；设备扩展发现只能在来源管理页面的显式操作路径执行。外部插件 manifest 恢复和已安装 runtime activation MAY 在首帧后的 capability handoff 中后台执行，但不得成为首封面硬门槛；该 handoff MUST 独立于 imported-library/download/queue durable-state 判定，只有 external-plugin manifest 的安装仍 MUST 能进入 Mihon/Venera 管理页且不得为此创建空 core SQLite。首次插件宿主打开失败不得把 settled null/error single-flight 永久复用于后续显式操作；显式来源管理 MUST 能重试。Home 封面等待 source readiness 时 MUST 保持 pending。显式来源管理操作仍可触发设备扩展发现与刷新；逐插件 source change 在 projection single-flight 退出边界到达时 MUST 被后继 refresh 消费，不得丢失。冷启动进入 Reader 或加载非 local-folder 章节前，MUST 等待对应外部来源就绪，不得在插件发布前构造空 responseLoaders 进入 Reader 或回退为本地文件/openLocalMediaResponse 读取。
- 首页每张封面 MUST 独立完成请求和显示；一张封面变慢或 durable response 写入变慢，不得阻塞其它已经取得 encoded bytes 的封面。冷 miss MAY 先使用 memory source，持久化写入由统一 response cache 后台完成；durable hit MUST 先物化为调用方自持有的 encoded bytes。response cache 的文件路径 MUST NOT 暴露给 `FileImage` 或其它长生命周期 presentation 对象；`FileEncodedResourceSource` 只允许外部稳定本地文件。durable image persistence MUST 区分 `transient` 与 `retained` 生命周期：browse/preview响应 MAY 受 TTL/LRU/maintenance 回收；library/history/details cover MUST 在同一 canonical cache key上晋升为 retained，并且 MUST NOT 被运行期容量/TTL整理删除。metadata refresh MUST NOT 以 comic namespace 粗粒度失效 artwork；retained cover仅由精确 artwork revision/显式整漫画资源删除/用户清缓存移除。

transfer时尊重实时priority并丢弃cancelled waiter；若同一scheduler `TaskControl`在waiter存续期间发生priority变化，gate MUST保留实时priority用于permit排序；只有waiter从低于1000跨入current=1000，或controlled MUST下沉到requestId cancellation。Venera controlled request-plan gate SHOULD以previous=780作为pressure floor并继续要求至少40分rank差：780对760不得抢占，780对明显更低rank active work MAY请求取消。`loadEp`的page identity与按需`onImageLoad` `Thread.sleep` 阻塞 WebView bridge线程。单上下文 invocation permit MUST等JavaScript真正 `finished(requestId)` 后才释放；仅向Dart返回“cancelled”不得提前制造第二个并发JS invocation。不得用独立FIFO覆盖NetLane决定，也不得增加Venera并发来模拟抢占。source MUST NOT因为该观测需求增加 timing callback；gate/runtime timing MUST限制在 resolve-resource 专用私有 invocation seam，普通 browse/details/account不得依赖该内部诊断。Venera source传给`Network.*`的`cache-time`与`prevent-parallel` MUST作为runtime network控制字段消费并在origin HTTP前移除，MUST NOT直接转发给服务器；Venera source-requested resolver cache MUST由native plugin-driver host/runtime-network SHOULD关闭response stream并保留平台持久连接复用机会，MUST NOT无条件disconnect；异常或request-scoped cancel MUST仍物理中止connection/stream。
- Native incremental decoder MUST NOT 在完整 WebP decode、scale、composite或 frame copy期间持有 encoded byte source读锁。source lock临界区 MAY 刷新 demux并复制下一帧所需压缩 fragment；耗时像素工作 MUST 在锁外完成，使前台 `reserve/commit` 不被后台整帧 decode阻塞。
- App presentation MUST NOT 直接创建 `HttpClient`/`HttpURLConnection`或直接消费 source transport。Venera `Network.*` 的 source runtime仍拥有Cookie、manual redirect、`cache-time`、`prevent-parallel`、requestId grouping与single-JS-invocation语义，但实际HTTP MUST由isolated plugin Dart process的reusable rhttp/reqwest resolver client执行；Kotlin/WebView bridge MUST NOT再持有第二HTTP client/connection pool。最终 media replay继续使用主流程rhttp direct transport；进程隔离允许两个owner-local client实例，但两者 MUST属于同一rhttp client family。
- host replay MUST 只用于可无状态平铺的单次 source request。遇到 redirect、`Set-Cookie`、未知 client wrapper、认证/session语义或成功 HTTP却非编码媒体响应时 MUST 切回 source-owned client；不得让独立 Dart HTTP client接管来源 Cookie/session状态。
- metadata/artwork MUST 经过 `ResourceCacheManager`；只有 Reader/章节 page body 与 artifact/download路径 MAY 通过明确命名的 page-body API绕过 response cache。插件仓库/APK/JS下载属于 control-plane，不得伪装成漫画 source response cache。 `CachedBrowsableComicSource` MUST NOT 暴露 artwork 加载 facade。`loadPageBytes` 与 streaming page loader MUST 共享同一 source-resolved response path；full-byte fallback MUST NOT 直接调用 raw source transport。章节下载的可变资源能力 MUST 作为单一 `ChapterResourceAccess` 原子绑定，不得使用多个 setter 形成半更新状态。
- 外部 artwork MUST 通过 source-confirmed canonical comic identity 查询统一 response cache；命中时不得解析来源、创建 source transport 或等待插件 activation。cache miss 才可进入source loader。raw Mihon/插件 locator只用于 runtime调用与章节身份，不得切分 durable artwork namespace。
- Home/阅读历史中已经持久化的 HTTP(S) artwork locator MUST 始终先进入统一 `ComicSourceResourceGateway` 的 source-independent memory/durable-cache probe；active source/plugin 暂不可用时不得把网络 URL 交给本地文件 loader。durable miss 后，若是首次外部 source 发布尚未完成，gateway MUST 保持该次请求 pending，再要求来源 adapter。
- 已挂载 Home 的 chapter/SavedComic mutation MUST 通过 `HomeLibrarySession` write-through投影边界完成：durable store写入成功后同一次操作必须更新 session可见投影；不得先直接写 store再依赖详情页退出或 `_reloadLibrary()` 追平。Reader route最终 progress MUST 为 route-local状态，返回后只发布一次；不得用跨 route全局 latest-progress槽。
- Home library reload MUST NOT 用 mutation 之前捕获的旧 entries/SavedComic snapshot覆盖更新后的 write-through chapter/saved/progress投影。
- Comic artwork基础 cache schema revision MUST 只有一个 owner。External artwork由 `ComicSourceResourceGateway` 自动添加 `comicArtworkCacheSchemaRevision`；调用方 MAY 只提供 content-specific revision，MUST NOT 再传基础 schema revision形成并行 namespace。
- 初次 external runtime activation 在 session建立前发生 Binder `runtime-service-died/disconnected` 时，generation continuity MUST 由 Android runtime-service client拥有；最多跨一个 service generation。Dart/plugin activation层 MUST NOT 通过再次调用 activation实现同一恢复，业务/ABI/请求错误 MUST NOT 被重放。
- 来源确认过的同源 canonical comic identity SHOULD 持久化在 SavedComic 元数据中，供插件未激活时的书架只读归并使用；原始 comic/chapter request identity MUST 保持不变。
- 未访问的首页、书架、来源和杂项导航页 MUST 延迟构建；首次访问后页面状态 MAY 保留，但隐藏页面不得为首屏预先创建封面 loader 或重复发起 cover request。
- Home primary、enrichment 和可选 runtime 的状态仍 MUST 由各自 owner 管理；不得新增 App 私有正文/图片缓存或让 UI 直接调度网络。
- “更新漫画” MUST 只显示当前已在书架且存在 source-confirmed update 的漫画。章节/目录变化 MUST 由 `SavedComicRecord.sourceUpdateAt` 表示；confirmed同源 successor/version MUST 由 `ComicVersionRelationStore` 的持久 relation及其首次 `discoveredAt` 表示，并由 `HomeLibrarySession` 投影供 Home/source browser 同步消费。版本 relation MUST NOT 通过写 `sourceUpdateAt` 来伪装成章节更新。presentation MUST 合并两个事实源排序；阅读进度、普通 metadata刷新、仅浏览/阅读记录 MUST NOT 推进它们。漫画源卡片 MAY 将 confirmed successor 投影为右上更新感叹号，点击时 MUST 可直接查看该 raw version；该提示不得把 successor伪装成已入书架。远程漫画缺少偏好记录时 MUST NOT 默认视为已加入书架；阅读历史 MUST 单独按 `ReadingProgress.updatedAt` 排序。

### 1.2 详情页与来源迁移

- 详情页顶部控制栏 MUST 不重复显示漫画标题；漫画标题只在详情内容区显示。
- 存在阅读进度时，详情页 MUST 提供可操作的“继续”药丸按钮；继续/阅读历史行 MUST 位于章节总数行上方，阅读历史 MUST 与按钮位于同一行并放在按钮之后，历史文字之前显示时钟图标。继续 MUST 通过既有`onOpenChapter` facade 打开保存的章节，不得等待无关的来源刷新。
- 来源漫画第一次打开后即使已持久化为 SavedComic，后续再次打开 MUST 复用当前已持有的 comic route identity lock，不得在同一调用链嵌套申请相同 `sourceId + comicId` 锁而静默吞掉导航。
- 详情页 SHOULD 同时提供通用“迁移漫画源”入口与同源版本快捷入口；来源提供 `ComicVersionSource` 时，同源候选 MUST 使用来源自己的版本关系（Venera/E-Hentai 使用详情页 `#gnd`），不得改为标题 browse 或要求浏览器页面权限；没有该能力时 MAY 回退到来源 browse 结果。入口展示不同原生 `comicId`，不得把当前版本再次列为迁移目标。来源确认的新版关系 MUST 可持久化，使后续打开新版时也能显示旧版；旧版和新版都可作为同源迁移目标。
- 迁移面板 MUST 显示当前插件和当前来源，目标源 MAY 是当前来源或其他已启用来源。相同 `sourceId` 的确认版本 MUST 在同一面板提供直接“查看”和“迁移”；跨源标题搜索只负责发现候选，MUST NOT 建立同源关系。相同`sourceId` 下不同 `comicId` 是合法的同源版本迁移，适用于 URL/gallery locator 变化；目标漫画及章节身份 MUST 在任何持久写入前校验。
- 迁移 MUST 只复制整部漫画偏好、精确章节匹配得到的阅读位置/已读状态和有证据的 artifact复用关系。目标写入成功后，同源替换 MUST 清理旧版本的漫画/章节元数据；跨源迁移 MUST保留原来源。来源专属 URL 和离线字节不得被当作可直接复制的元数据。
- App-owned modal panel 的关闭操作 MUST 是左下角 X；确认、保存、删除等正向操作位于右侧，不得以“取消”文字按钮替代关闭 X。
- 漫画源页 MUST 使用来源自身声明的 browse section；Mihon Popular/Latest 与 Venera explore/category target 均属于来源内部分类。原生/Mihon/Venera 运行时类型 MUST NOT 作为内容分类行，只能以来源 chip 的视觉标识区分。固定大小 catalog page MUST 使用显式上一页/下一页，pager MUST 位于内容滚动尾部；切换来源、section 或外部搜索请求时 MUST 回到第一页。
- 切换漫画 source 时，Presentation MUST 在同一更新周期将 projection owner切换为目标 source；MUST只使用**当前 Presentation request identity**的目标精确缓存直接投影，没有精确缓存时显示目标 loading/error并按当前 section/query/filter请求加载。Catalog可保留目标最近 projection作为诊断/内部 cache事实，但 MUST NOT用它反向改写 UI默认 section/query/filter。旧 source页面不得因目标请求失败继续可见。
- 强制刷新遇到 `sourceVerificationRequired` 且存在 WebView capability 时 MAY 自动进入一次目标 source验证。**任何一次**手动或自动验证浏览器 handoff都 MUST 消耗该 `sourceId + request URL` 的自动 fallback机会；若恢复重试仍失败，后续普通刷新 MUST NOT循环打开 WebView，只保留错误诊断和手动恢复。成功 browse后 MAY 清除该 guard。
- Cloudflare WebView恢复 MUST 优先打开 typed failure中的实际 request URL而非仅打开 source homepage；打开浏览器 MUST NOT预先删除已有 Cookie/snapshot。WebView `onPageFinished` MUST NOT直接等价于验证完成。浏览器内部 SHOULD 使用比网络 classifier更保守的 challenge探针，并且 MUST 要求同站点、`document.readyState=complete`、WebView progress=100以及连续稳定窗口内无可见 Turnstile/challenge form/running容器/`cf-chl-*`/challenge iframe或典型验证中间态，才可完成当前 Cookie/UA snapshot handoff；不得把“必须生成新的 `cf_clearance`”作为唯一成功条件。已有同站点/同 UA snapshot在新页面成功 capture前 MUST 保留，空 Cookie capture MUST NOT破坏已有非空 handoff。
- Cloudflare 验证浏览器 MUST 使用当前 Android WebView provider 的真实 User-Agent，MUST NOT用插件/OkHttp 的静态 UA覆盖验证 WebView。Cookie、localStorage 与真实 WebView UA MUST 属于同一 snapshot revision；Mihon runtime消费该 snapshot时必须让同站点 OkHttp请求采用同一 snapshot UA，并同步导入其 Cookie。
- WebView 验证返回后外部 runtime MAY 被重启。详情页与漫画源页的后续操作 MUST 按稳定 source ID重新解析当前 active adapter，MUST NOT继续调用重启前已关闭的 session。漫画源页 MUST 在 replacement source上重新加载 section/filter后再强制刷新，并禁止同一次恢复再次自动打开 WebView。
- `sourceVerificationRequired` MUST 只来自 typed host challenge detector：`cf-mitigated: challenge` 可直接确认；否则 MUST 同时满足 HTTP 403/503、Cloudflare Server header 与 `challenge-error-title`/`challenge-error-text` 交互 challenge DOM。`challenge-platform`/`cf-chl-*`脚本、`Just a moment`标题、Cloudflare header单独存在、普通 HTTP 403、timeout、解析失败和包含 Cloudflare字样的异常消息 MUST NOT被重分类。主网络与兼容 interceptor MUST使用同一 detector，不得使用隐藏 WebView。
- 漫画源搜索 MUST 以来源栏上方的浮动控件进入，展开后 SHOULD 提供可持久化、可删除和可清空的搜索历史。展开搜索面板 MUST 优先消费系统返回手势与垂直拖动/滚动手势，并在这些手势发生时恢复为浮动按钮。搜索展开和文本输入 MUST 只更新搜索子树，MUST NOT 重建 catalog 网格；IME inset MUST 只按键盘与浮层原始位置的实际重叠量移动搜索浮层，不得重复补偿其到底部栏的既有净空或压缩整个漫画源页，固定搜索浮层与底部来源栏 SHOULD 使用独立 repaint boundary。IME 开始收起时 MUST 释放输入焦点但保留面板，收起动画期间再次返回 MUST 只关闭面板且 MUST NOT 重新弹起键盘。Mihon `getFilterList()` 返回的 Header、Separator、Select、Text、CheckBox、TriState、Group 与 Sort MUST 由 bridge按 Mihon基类继承关系完整投影，MUST NOT以插件自定义 concrete class名称猜类型或拍平 Group；空 `FilterList` 表示该 source没有筛选入口。用户修改 MUST 以类型化 filter-state override返回 source search调用，Text字符串与 Sort的 index/ascending不得压缩成 toggle ID。 “筛选” MUST 是可获得焦点的独立浏览视图；点击后即使不修改任何选项，直接应用也 MUST 以 source `FilterList` 默认状态执行 filtered browse。空 override MUST NOT 被解释为 ordinary Latest/Popular。筛选视图激活时 MUST 取消 Latest/Popular焦点，filtered request/cache identity MUST NOT继承先前 section；是否使用筛选 MUST 作为独立 request mode传至 Catalog/runtime。External plugin browse wire validator、typed request factory与 source adapter MUST 对同一参数集合保持一致；同一 schema版本内新增可选字段 MAY 缺省为兼容默认值，但未知字段与错误类型 MUST继续拒绝。标准 section Presentation顺序为“最新 → 热门”，首次进入来源时 MUST 选择当前展示顺序的第一项；catalog最近缓存 MUST NOT反向决定默认 section/query/filter。未来若用户自定义排序，默认项 MUST继续由同一个展示顺序 owner的第一项派生。筛选动作打开 filter 面板，MUST NOT 把插件 Filter伪装成 `SourceBrowseSection`，浮动搜索仅拥有 query/历史。browse metadata projection变化 MUST NOT 作为 artwork reload revision；source card direct-child State MUST 使用 canonical comic identity，raw locator或无关 page projection变化不得重置已就绪封面。 漫画源卡片的“已入书架”视觉状态 MUST 从 Home/library canonical preference projection读取；已入书架封面 MUST 在左上使用明确书本/书架标志并降低亮度，source browser MUST NOT维护第二份 shelf membership；source-confirmed update提示与书架标志 MUST 分离显示在右上。搜索结果 MUST 使用 catalog/resource-cache 权威：若有**当前精确请求**缓存，Presentation MUST先显示缓存并后台刷新；只有稳定字段变化时才替换列表，不得建立页面私有结果缓存。漫画源页 MUST 支持边缘下拉达到阈值后的强制刷新；强制刷新 MUST 绕过 catalog cache，但 SHOULD 保留已有内容直到新结果到达。
- Mihon 插件的已安装列表和仓库列表 MUST 能按规范化语言分类；语言 SHOULD 优先使用插件声明，缺失时从插件 source metadata 推导。多个语言 MUST 归入多语言，无法可靠确定时归入未知语言，不得从显示名猜测。
- 搜索框退出时 MUST 关闭扩展搜索选项并在下次展开时默认收起；收起状态的悬浮搜索按钮长按 MUST 进入聚合搜索结果视图。
- 搜索框右侧 MUST 提供默认关闭的关键词锁定控件；未锁定时搜索关键词 MUST 只作用于当前提交请求，提交后 MUST 清空输入和内部 query，后续翻页、刷新、切换来源或分类 MUST 使用空 query；锁定时 MUST 保留关键词并允许后续浏览继续使用。
- 聚合搜索 MUST 遵循相同锁定语义；非锁定聚合提交后 MUST 关闭聚合模式、清空输入和聚合 query，但 MUST 保留已经返回的聚合结果。收起状态搜索按钮的点击与长按 MUST 由同一外层手势 owner 分发，长按 MUST 能进入聚合结果视图。
- 最近一次聚合结果在来源列表未变化时 MUST 保留为内存投影；切换当前来源 MUST 只退出结果页并关闭搜索框聚合模式，不得清除该投影；再次长按搜索按钮 MUST 直接显示该结果及其查询标题，不得显示空结果提示或重复请求。
- Mihon APK 识别 MUST 接受 manifest 中直接字符串或字符串资源形式的 extensionLib/entry class metadata；多个 entry class MUST 支持逗号、分号或换行分隔。候选识别 MAY 使用标准 extension feature/package prefix，但加载前仍 MUST 完成 package、signer、version、ABI 与 entry class 校验。
- Android 上 Mihon 共享扩展发现 MUST 至少合并系统包枚举与已知 package name精确探测；单个 APK 识别失败 MUST 保留 package、阶段和错误信息，不得被转换为空列表。系统包可见性受限时 MUST 向用户显示诊断。Mihon 私有 App目录不属于可访问的系统扩展边界，UI MUST 引导用户从 ZIC仓库安装，而不得声称已读取该目录。
- Production external-plugin runtime MUST use an explicit bounded active-session safety ceiling large enough for mixed installed sources; current composition sets 32. The generic test/embed default MUST NOT silently become a user-visible eight-plugin limit.
- plugin host MUST NOT 把 network bridge 的内部 browser-cookie session实现列为 Mihon common runtime ABI。Cookie snapshot reset MUST 通过稳定网络适配器边界调用。
- Mihon common runtime完整性预检中所有 `dev.zic.network.*` 动态类型 MUST 在 network bridge consumer R8规则中保留原始全限定类名和成员；typed `SourceVerificationRequiredException` 不得被混淆、裁剪或用错误消息字符串替代。
- app startup channel 通过类名反射挂载的 feature plugin 和 rhttp entry MUST 在 app R8规则中保留原始全限定类名及可调用成员；release APK 不得因 `Class.forName` 入口被混淆或裁剪而返回 `ClassNotFoundException`。
- 外部插件持久 manifest MUST 逐记录容错；一个坏记录不得清空其它已导入插件。写入 MUST 保留上一代 `.bak`；启动恢复 SHOULD 依次尝试主 manifest、`.bak`、残留 `.part` 和旧 `.invalid`，并允许旧 sandbox绝对 payload路径按 owned-root basename迁移。恢复记录仍 MUST 经过原有 payload hash、签名、ABI和 entry class检查。
- 详情漫画、章节、预览首屏/分页和评论首屏/分页 MUST 使用与漫画源页/搜索相同的 `ResourceCacheManager`，但 MUST 以漫画详情、预览分页、评论分页各自的稳定 response identity 分区；不得以详情页私有缓存复制 catalog cache owner。预览图和评论头像的编码字节 MUST 继续走统一 artwork cache，不能进入 metadata response cache。
- 进入详情页时 MUST 先投影可用热详情数据，再异步刷新主详情和可选预览/评论元数据；章节、漫画字段、预览页和评论页 MUST 分别比较，只有对应类别稳定字段变化时才替换该类别投影。可选请求失败 MUST 保留旧类别数据，不能清空已显示内容。强制主响应若携带内嵌首屏，MUST 更新对应分页 projection；普通主响应缓存命中不得覆盖独立分页刷新结果。
- 详情首帧 MUST 不等待下载状态检查、artifact index/page I/O、跨版本 page mapping warmup 或 source request-plan；下载状态检查 MUST 在首帧后批量读取并合并同一路由的重复请求，版本 discovery/mapping warmup MUST 在首帧后后台执行。
- 详情页与漫画源页的章节 presentation key MUST 保持为 `source-chapter:${sourceId}\u0000${chapterId}`；`sourceId` 或 `chapterId` 任一变化 MUST 产生不同 key。已读滑动容器和下载按钮可使用各自的 `chapter-read:`/`chapter-download:` 前缀，但不得把标题、sequence、URL、sourceRevision 或缓存 response identity 放入章节身份 key。
- 章节行的右划 MUST 切换当前章节的已读/未读状态，不得因当前状态禁用该方向；UI MUST 先完成投影，章节补齐和已读持久化 MUST 在后台完成，不得阻塞手势。`chapter_read_state` MUST 能在章节尚未 hydrate 时按 `sourceId + chapterId` 独立持久化，不得通过指向章节表的外键强制先获取章节信息。左划 MUST 只露出最右侧垃圾桶，点击后才触发删除，不得在滑动结束时自动删除；即使章节尚未 hydrate 也必须显示该入口，只有点击垃圾桶时才允许后台补齐完整 entry。已缓存章节支持长按打开删除确认框；删除 MUST 同时清理章节记录、阅读进度、已读状态和离线页面，且删除实际使用完整 hydrated entry。
- 来源详情若提供预览能力，详情页 MUST 能先显示 `ComicManifest` 中已经返回的预览项，后续页 MUST 通过 `ComicPreviewSource` 独立加载；预览图片必须复用统一 artwork loader，不得为详情页建立专用图片缓存或等待其它章节/评论请求。Venera 的 `@x/y` 裁剪标识MUST 保留在预览项和绘制身份中，同时传给 `onThumbnailLoad` 的 URL MUST 去除该标识；去除后的原图 URI MUST 是编码字节缓存和实际请求的身份，使同一原图的不同裁剪只产生一次请求/缓存项；宿主绘制时 MUST 只显示该标识指定的原图区域。图片失败时 MUST 使用按资源identity 稳定生成的柔和纯色占位，不得显示破损图片图标。预览栏折叠与展开 MUST 使用同一套排版结果：折叠态只显示第一行，高度由该行实际高度决定；展开态继续自动消费来源分页并以 `PageView` 左右分页呈现后续行。预览项 MUST 尽量保持来源原始顺序，并在可读尺寸下放置尽可能多的图片。完整行 MUST 直接使用全部媒体宽度反算等面积 tile，不得以外层 Card、重复水平 padding 或扩大 item gap 消耗剩余宽度；只有稀疏末行 MAY 放大到参考完整行面积的 2.4 倍。实际行含横图时最多 2 项，纯竖图行最多 3 项，并受用户设置的更小上限约束。阅读设置 MUST 提供每行最大数量 1–8，默认 4。图片区域 MUST 不超过屏幕高度的 90%，展开/收起按钮 MUST 居中且只显示箭头，不得显示“展开/收起”文字。不得拉伸、强制裁切或建立详情页专用图片缓存。
- 来源详情若提供评论能力，详情页 SHOULD 显示评论栏，并 MUST 支持分页评论次级页；评论存在回复数量和不透明 ID 时，次级页 MUST 能按原 source `subId`/回复 ID 加载回复。这些能力是可选的，来源未声明时不得发起插件请求。评论正文的受限 HTML MUST 将 HTTP(S) `img` 交由统一 artwork loader 作为行内图片并支持 `br`/HTML entity；不得把原始 `<img>` 标签显示为文本或建立 emoji 私有网络/缓存 owner。

## 2. Reader 行为

### 2.1 Current 与输出连续性

- current MUST 具有最高 download、decode 和 upload 优先级。
- near/far 工作不得阻塞 current；current 的 holder/播放状态也不得冻结目标页网络。
- verified-equivalent physical alias MUST只共享physical artifact/writer/retry状态；当前consumer选择source transport后，实际full/range/resume request MUST使用该consumer的exact `DownloadId.canonicalUri`，MUST NOT把physical anchor URI泄漏到另一个版本consumer的transport。
- acquire-time verified physical alias的Reader网络进度 MUST直接投影resolved physical `DownloadSession`的`networkStartLength/committedLength/totalLength`；Pipeline MUST NOT按logical exact `DownloadId`建立第二份authoritative progress session表，Reader MUST只消费只读进度projection。
- 已有 output 在 replacement 前 MUST 保持可见；缺少动画 successor 时保持当前帧并等待 producer。
- loading MUST 绑定到具体媒体区域，不得用全局 overlay 隐藏已有页面。

### 2.2 翻页

- stable ownership midpoint 默认为 50%。
- 横向目标页覆盖率达到 0.15，纵向目标页真实进入视口时，MUST 建立 transition demand。纵向 `targetCoverage` MUST 只来自真实可见的非 current page；只有 current 可见时 MUST 为 null，MUST NOT 从 `logicalPosition` 的 page-local fraction 通过 floor/ceil 虚构隐藏 target。仍在 viewport 内的 outgoing page MAY 继续作为 transition，直到其真实离屏。
- current 浅水位 bootstrap MUST 优先：动态 current holder depth < 3 时，speculative next/next2/previous 不得启动新的 decode refill；静态 current 一帧即满足。若 current 暂时在等待 source，真实已进入 viewport 的 transition MAY 独立取得一帧，避免拖动目标黑屏。
- current bootstrap 建立后才恢复 next/next2/previous staged refill；transition 不得用深水位抢占 current 的基础播放水位。
- midpoint 后新 stable page MUST 成为 current；旧 current 的已上传 output MAY 作为独立 retained/last presentation 保留并暂停播放，但该 retention MUST NOT占用或跳过相对 previous/next slot。相邻旧 current仍 MUST按 offset -1/+1参与 encoded/decode window；大跳后若已离开7/3窗口则 retention不得单独制造 download/decode demand。
- 交接不得产生 targetless demand gap、黑屏或重新创建同一 identity。

### 2.3 连续模式与控制

- 内容 MUST 等比呈现，统一使用 `height / width`；不得裁切正文，或用负位移、重叠和多套比例公式掩盖接缝。
- Reader MUST 支持沉浸、跳页、暂停、倍速、方向和布局命令；命令只通过 Reader facade 提交。
- Reader slider MUST实时跟随拖动跳页：`onChanged`更新UI preview并通过Reader-owned scrub navigation推进PageView/current page；不得等到`onChangeEnd`才改变可见页。scrub observation MUST显式标记`Interaction.scrubbing`，其Pipeline计划只能包含当前页foreground download/decode/upload，不得逐格展开7/3 prefetch窗口；`onChangeEnd` MUST在最终页结束scrub并恢复正常完整窗口。viewport acknowledge前slider仍以preview/requested page作为受控显示值，不得被旧`currentIndex`回拉。
- Reader 页码或阅读模式改变后 MUST 通过既有 progress facade 持久化 `ReadingProgress`；Applifecycle 进入 inactive/paused/detached 和 Reader route dispose 时 MUST 强制 flush 最近进度。Home projection MUST 在写入成功后立即更新，不能要求先退出详情页才反映阅读历史。
- Reader 正常返回前 MUST 等待最终 progress writer drain；详情页等待 Reader route返回后 MUST 立即重读本地 snapshot。异常进程终止只能依靠持续 checkpoint降低损失窗口，不得宣称绝对 crash-safe。
- UI 控件存在性 MUST 来自 capability，不得用静态/动画猜测下载或播放能力。
- 双击缩放分级与长按放大 MUST 可设置：双击循环 1x → 一级（默认 1.5x）→ 二级（默认 2.0x）→ 1x；长按放大分页模式默认开启，连续模式默认关闭且仅可按漫画单独开启。
- 分页模式长按放大释放行为 MUST 可设置，默认松手复原（松手后动画回到 1x 并恢复翻页滚动）；关闭后放大保持到双击退出或页面切换。连续模式长按放大 MUST 始终保持放大，不得松手自动复位。
- 长按放大移动方式 MUST 可设置为拖动或聚焦。拖动模式内容位移 = 手指累计位移 × 拖动比率（默认 1.0，即按放大后分辨率 1:1 跟随；比率可设 0.25–4），聚焦模式保持手指下的内容点始终位于手指处（位移 = p·(1−s)）。拖动实现 MUST 以长按起点平移为基准应用一次累计位移，MUST NOT 逐帧重复累加导致失控。
- "最大可视"边界约束（默认开启、可设置关闭）MUST 按实际显示图片矩形计算，而非页面控件矩形：contain 留边时以图片边缘为准——缩放后图片能覆盖视口的轴，一侧越界则对侧不得越界；不能覆盖的轴保持图片居中。关闭后允许自由拖出视口。
- 双击放大的结果位置 MUST 可设置：居中（以视口中心为原点）、吸附（按点击半侧把图片对应边缘贴齐视口边缘，覆盖不了的轴居中）、聚焦（保持点击位置不动）。默认居中。
- 连续模式的缩放（双击分级、捏合与长按放大）MUST 作用于整条页面序列的统一变换：所有可见页一起缩放，接缝不得分裂。放大是视口空间的视觉层：列表滚动 MUST 保持可用（可在放大状态下继续滚动切页），跳页/滑动不得自动复位缩放；仅方向切换/换章节等结构性变更复位。
- 连续模式放大后双指捏合松开 MUST 保持结果倍率与偏移，不得因倍率低于阈值自动弹回 1x。已在放大态时长按 MUST NOT 跳变倍率，仅按移动方式调整水平偏移并在松手后锁定。
- 双击的第二下按住超过长按阈值时 MUST 触发"固定水平偏移锁定"：放大态保持当前倍率并固定整条 strip 的水平偏移，按住期间 MUST 禁用水平方向拖动；从 1x 开始时 MAY 进入一级倍率。松手保持倍率与偏移，且 MUST NOT 触发单击呼出控制栏。锁定态再次普通双击 MUST 仅退出锁定并保持当前倍率；解锁后的普通双击才继续离散阶段循环。双击配对 MUST 使用屏幕坐标判定（strip 变换会使局部坐标在动画期间漂移），且 MUST 用离散阶段索引推进 1x → 一级 → 二级 → 1x：快速连续双击 MUST 单调步进，MUST NOT 因动画中间值回退到更小倍率。未锁定时普通单指水平滑动 MUST 平移整条 strip；锁定时 MUST NOT 改变偏移，从而以固定偏移从视觉上整体裁切漫画边缘；双击第二下按住期间 MUST 独占指针：禁用垂直滚动切页，松手恢复滚动并锁定倍率与偏移，且 MUST NOT 触发单击呼出控制栏。双击/再放大换级时 MUST 以"保持锚点内容不动"计算目标偏移（offset' = f − s'·((f−o)/s)，除以当前倍率；一级进入时 s=1 退化为既有公式），二级及以上的偏移 MUST NOT 按一级偏移基数计算。分页和 strip 的二级换级都 MUST 按当前倍率换算锚点并使用实际缩放图片矩形进行边界钳制；缩放动画 MUST 直接向解析后的目标帧插值且逐帧按当前倍率钳制偏移，MUST NOT 先按旧偏移播放再二次修正产生回跳或过程越界。strip 处于放大态时延迟比例提交（provisional→measured）MUST 冻结，不得在放大镜下改变内容尺寸；回到 1x 后立即落盘。缩放倍率变化经 `onZoomScaleChanged` 投影给解码提升，仅为可视区域提高解码分辨率且不超过原图。

## 4. 网络调度

- composition-owned `NetLane` MUST 是页面网络的唯一调度权威。
- current SHOULD 使用 priority 1000；network/decode/upload可各有一个current-only bounded handoff。network `NetLane`在normal 5槽满时 MUST先用唯一reserved槽直接admit current，MUST NOT仅为借该槽先取消running task；只有normal+reserved均饱和且current仍blocked时 MAY按统一effective rank与40分margin preempt。priority 780/800/820/900的normal work MUST NOT主动取消仍有consumer demand的active task来抢普通槽；只有`demanded=false`的already-admitted inactive task MAY在真实容量阻塞时由NetLane统一reclaim。破坏性network preemption MUST具有NetLane-owned incoming candidate stability：Reader当前100ms；candidate未连续保持high-priority blocked至窗口结束前 MUST NOT cancel active victim，但free/reserved slot admission MUST仍立即发生。每个NetLane MUST最多允许一个scheduler-preemption victim处于cancelled但尚未物理退出状态；该victim退出前其他blocked current MUST只排队/更新rank，不得继续cancel更多active transport。scheduler/consumer typed cancellation MUST只结束transport attempt；若writer已有authoritative bytes，DownloadJob MUST先flush再pause，DownloadSession MUST回`idle/failure=null`并保持committedLength/Ingress/epoch，MUST NOT写成`DownloadState.failed / Failure(cancelled)`。already-admitted task在logical claim归零后 MUST迁移rank0而不是由Reader/session直接cancel；queued且从未admit的undemanded work MAY直接移除。普通可Range-resume的committed partial不得仅因字节较多自动变成不可抢占sunk cost；victim经济性仍由统一`NetPolicyRank`的真实不可恢复restart cost决定。consumer-bound transport真实dispose、任务错误、显式用户取消仍可硬终止。
- DownloadJob、Reader、UploadSession 和 holder 不得建立第二套网络资格门控。
- 目标页 receiving transport 不得因 current holder depth、播放 underflow 或页面控件状态被暂停。
- 不得缩小**逻辑/retention 7/3或DownloadDemand 7/3**、关闭预下载或降低播放速度掩盖 identity、重复请求或 producer wake 缺陷；动画WebP只能在同一physical task内用frame credit与typed flow-control capability控制远端body流量，不能恢复2/4 eligibility、whole-body估算budget或cancel/reopen式流控。

## 6. Animated WebP

- 两个 Dart decode isolate MUST 在 App 运行期常驻；libwebp 帧内 MUST 单线程。
- 首次 decode SHOULD 优先单帧；current 后续 MAY 每次批量返回最多两帧。

- current bootstrap MUST 先建立静态1帧或动态最多3帧的浅水位；bootstrap 未满足时 speculative neighbor refill MUST 为0。current 等 source 时，真实 transition depth=0 MAY 独立取得1帧；bootstrap完成后恢复 staged current/neighbor refill。

- metadata 未完成且 source 增长时 demux MUST 可刷新；未封缄 need-more-data MUST 等待 source revision，而不是定时销毁 cursor。
- source revision MUST 保持 pending，直到对应 DecodeSession 实际执行 fill，或其当前 snapshot 明确证明无需 fill；staged refill policy 因 current bootstrap 暂时返回空决策 MUST NOT 被解释为 source 已消费。角色晋升为 current 后 MUST 能从 projection 当前 revision/state 重新发现已就绪 source。 DecodeSession的generation authority MUST唯一来自当前Reader-local ingress projection；MUST NOT同时读取physical DownloadSession epoch进行第二份preflight。若projection epoch在异步decode期间变化，旧work MUST按生命周期cancel而非terminal decode failure；若projection在同epoch内rebuild并替换`EncodedSource`实例，DecodeSession MUST丢弃绑定旧实例的cursor/holder并从当前source重新创建cursor。LiveCoordinator MUST NOT把返回`failed/failure`的DecodeSnapshot记为已消费source revision。 Reader ingress registry的`get(session)` MUST区分physical object generation与Reader encoded generation：same DownloadId的新physical session仍属于新的physical object generation；unfinished/failed或仍有pending synchronized attachment的same DownloadId新physical session MUST创建fresh Reader-local projection/source；若existing projection已经sealed、sourceReady、无failure且无pending attachment，则same exact DownloadId的transient DownloadSession recreation MAY保留同一immutable Reader encoded generation，并 MUST NOT因此invalidate decode/upload。旧same-id physical teardown MUST做concrete session identity校验。synchronized late join MUST在加入physical live fan-out前同时证明physical boundary稳定且projection snapshot的epoch/length/sealed/failure精确闭合，MUST NOT仅因physical revision未变就宣称incomplete projection已attached。UploadSession在physical-generation invalidation触发的dispose MUST立即退休当前uploader slot并清除deferred-release请求；旧generation pending prepare随后结束 MUST NOT再次按logical DecodeId release replacement generation。普通demand detach的pending-upload release语义保持不变。 UploadRegistry MUST把logical DecodeId与concrete DecodeSession generation区分：`get/prepare`命中既有UploadSession时 MUST验证`identical(existing.decode, decodes.get(id))`；不一致时 MUST先dispose旧UploadSession再创建replacement，MUST NOT把旧holder为空解释为当前DecodeRegistry仍无frame，也MUST NOT让UploadSession在生命周期中动态切换DecodeSession。
- native target canvas MUST 生成预乘 RGBA；Flutter fallback output与Android production output均不得再次预乘。
- finite animation 到 EOF MUST 保留最后一帧；静态零时长帧不得启动 playback timer。

## 7. Upload 与 renderer output
- Texture bridge 的 `scheduleFrame()` 合并边界按 `SurfaceProducer` 独立计算，并保持到下一次 Android vsync；合并只减少重复平台消息，不改变最新 resident frame 或 MethodChannel 完成语义。

- 生产Reader Android SurfaceProducer output MUST使用一个串行blit lane，`scheduleFrame()`和MethodChannel result必须在platform thread有序完成；同一 output 在主线程忙于 Flutter frame 时 MAY 合并待调度回调，但 MUST 对每个调用完成回调，且以最新 resident frame 执行一次真实 `scheduleFrame()`。

## 8. Reader 资源会话生命周期

- Reader Host MUST 通过 factory acquire/release 资源会话，不能在 Widget dispose 中直接销毁所有章节资源。

## Artwork 与插件会话稳定性要求

1. 失败封面不得因父组件 rebuild、App resume、timer/watchdog或第二个 ImageStream自动重新发起请求；Presentation MUST 保持稳定占位，只有显式来源刷新、资源 revision或稳定 identity变化才允许重新加载。
2. 实际预览行含横图时 MUST 最多 2 项，纯竖图行 MUST 最多 3 项；为满足该规则 MAY 在相邻三个候选内做一次最小局部重排，并受用户设置的更小上限约束；不得用额外间隔消耗剩余宽度。
3. 详情与漫画源下拉刷新 MUST 共用同一个组件拥有 edge trigger、位移、刷新进度和成功/失败反馈；结果图标 MUST 与刷新指示器使用同一落点。

4. encoded artwork source 已就绪后，普通 artwork MUST 只创建一个 ImageProvider/解码监听；需要裁剪或尺寸测量的 Presentation MAY 显式监听一个 ImageStream并直接绘制 decoded image，但 MUST NOT 同时构建第二个 `Image`监听同一 provider。
5. 远程详情 MUST 先显示已有 catalog/detail cache，并等待当前 active source adapter 完成后台刷新；主详情、章节、预览和评论 MUST 按元数据类别增量替换，预览、评论及章节操作 MUST 在调用时解析当前 adapter，不得持有插件重启前的关闭 session。详情 route 的首帧 MUST 不依赖下载状态/artifact I/O 或跨版本 mapping warmup。已持久化的同源 successor/predecessor MUST 先于网络发现投影，网络只在后台校准；版本入口 MUST 与“下载整本”保持同行且使用固定占位，无版本关系/加载中不绘制图标，不得迟到插入整块 UI 改变布局。面板 MUST 在同一层切换新/旧版，标题点击直接查看详情，行尾迁移直接进入对比；列表 MUST 显示可读标题和日期，MUST NOT 显示 opaque ID 或 source 伪 generation。正文喜欢、书架、收藏和下载 MUST 保持统一 48×48 `_PreferenceButton` 尺寸，不得因不可见版本槽整体缩小。版本入口 MUST 位于顶部 AppBar“迁移漫画源”控件左侧并复用标准 `IconButton` 风格；无关系时仅保留标准 action 空槽。缓存首显后的 source refresh MUST 更新当前 route/面板。“迁移到当前版本”只在存在非当前 canonical predecessor 时可用，并 MUST 进入迁移对比。同源替换对已验证等价的 durable source artifact MUST 物化为目标 exact DownloadId，确保移除旧记录或重启后仍不重新下载；未验证页面 MUST NOT 复用。
6. Mihon chapter catalog MUST 只投影插件/source API实际返回的完整 `SChapter` 列表。TachiyomiX 1.6/current Mihon MUST 先调用 `getMangaUpdate(manga, existingChapters, ..., fetchChapters=true)`；只有 combined能力明确不存在时 MAY回退 legacy `fetchMangaDetails/fetchChapterList`。正文 MUST先调用 `getPageList(SChapter)`，只有能力不存在时 MAY回退 `fetchPageList`。成功空列表是合法结果；真实调用错误保持失败。MUST NOT 从 manga URL生成兼容单章，也不得按标题、`SChapter.url`、number或sequence推断、增加、删除或合并章节。

11. Mihon/外部插件同 pluginId 的 runtime restart或更新 MUST 使用事务式 replacement：候选 session先完成 activation、source identity/ABI等验证，成功后才能替换当前 source owner并关闭旧 session；候选失败 MUST 保留旧 session。不得先 deactivate再尝试 activate。

## Download storage / transfer detailed contract

The detailed normative contract for storage roots, direct/SAF access aliases, sparse version materialization, cache/export retention, partial+network continuity, failure feedback and Reader/manual shared resource scheduling is [`DOWNLOAD_STORAGE_SPEC.md`](DOWNLOAD_STORAGE_SPEC.md). During the staged refactor, existing durable formats remain compatibility inputs, but new behavior MUST preserve the contract there: no global N-dependent page remapping, no speculative per-page expansion for unopened versions, no UI-owned local/network stream concatenation, and no assumption that changing default export root invalidates readable replicas on older roots. The production App-level `DownloadResourceCoordinator` owns the current network and persistent-artifact local-read lanes; Reader Pipeline and persistent download composition MUST consume the same injected authorities rather than creating competing production lanes. A persistent-tier foreground cache hit MUST expose `ArtifactCacheStreamEntry.open()` directly and MUST NOT invoke `readAll`/whole-body collection before its first Reader chunk; an existing memory-tier hit MAY use the direct byte body. The remote Reader entry path MUST NOT call `readyPageIndices/readPage` to manufacture a second local full-byte loader for indexed artifacts; it MUST register origin response capability and let `ArtifactCacheTransport` resolve persistent local authority first.
