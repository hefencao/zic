Download storage boundary refactor baseline (2026-09-06): the accepted target architecture is documented in `docs/DOWNLOAD_STORAGE_ARCHITECTURE.md` with normative behavior in `docs/DOWNLOAD_STORAGE_SPEC.md`. Production still uses several transitional representations: download-root-coupled metadata in direct mode, `CacheRec.path` as a logical/physical combined record, SAF/direct as mutually selected modes rather than proven aliases, and full-prefix copy during durable partial restore. The generic `local_media_ui` loader+response recovery wrapper has been removed; the UI now rejects dual local/origin capability for one page, so recovery authority is reserved for the artifact/transfer layers. These are migration targets, not new architecture authority. Refactoring must proceed by independent functional commits, preserving current durable compatibility and existing user data at every phase. Phase 1a/1b is complete: production App composition creates `DownloadResourceCoordinator` and injects the same `NetLane` and `ArtifactCacheReadScheduler` into both the default Reader factory and persistent download composition; storage-write/migration lanes have not moved yet. Phase 2 transport streaming is complete: cold persistent foreground hits bypass `readForegroundLookup/readAll`, stream directly from the backend entry, and acquire the foreground local-read lease lazily on body consumption; memory-tier hits keep the direct hot-byte path. Phase 3 Reader entry cleanup is complete: remote chapter preparation no longer calls `readyPageIndices/readPage` or constructs local full-page byte loaders; all page origin response loaders remain available and persistent local resolution is delegated to the shared artifact transport. Phase 4 UI recovery ownership is complete: dual local/origin page capability is rejected by `local_media_ui`. Phase 5a typed access failure foundation is implemented: `ArtifactReadFailure` carries the six target causes plus failed offset/emitted bytes; POSIX/SAF streaming emits applicable missing/access/stale/short-read/I/O causes and Android SAF preserves typed bridge codes. Phase 5b persistent failure enrichment is implemented: `CacheRec.effectiveArtifactId` is attached as `replicaId`, recorded-vs-physical mismatch surfaces as `lengthChanged`, access-only failures preserve the SQLite binding/physical bytes, and mid-stream failures retain emitted offset. Repository lookup still tries existing verified-equivalent candidates before surfacing the first replica failure. Phase 5c Transfer recovery is implemented: pre-body cache/repository failure may fall back to origin in the same open; a typed persistent-body failure after any local prefix terminates that response without stream splicing, quarantines that logical persistent read for the current ArtifactCacheTransport lifetime, and lets the next Transfer attempt reopen origin. Structural missing/stale/short/length failures invalidate the affected durable binding, while accessDenied/ioFailure preserve it. Resident artifact-cache failure resets only the ephemeral transfer projection (`removeCacheRecord: false`). Phase 6 export page-order ownership is implemented: Reader no longer derives order from download placement; per-comic inversion is effective only while comic-specific Reader settings are enabled. `auto` freezes before first structured materialization from verified single-chapter pure-front-prepend evidence or falls back to `origin`; SQLite schema 6 adds sparse immutable `export_page_binding.exportOrdinal`, ordinary front-prepend/version-chain reuse preserves old ordinals without global `N-index`, and unmaterialized intermediate versions remain row-free. Whole-comic queue persistence/recovery carries the frozen page-order intent into the placement claim. Existing-slot movement is rejected as policy pending a future explicit Export Relayout boundary. Phase 9 structured-image validation now makes actual bounded byte signatures authoritative for export extension: JPEG/PNG/WebP/GIF/BMP/TIFF/ICO/AVIF/HEIF are recognized, generic ISO-BMFF `ftyp` no longer aliases to AVIF without a matching brand, unknown-hint valid images materialize under their detected extension, and unsupported/non-image bodies fail as `artifactCorruption` rather than being blessed by `ContentKindHint`. First-class multi-root replica records and resident-prefix-to-partial adoption remain deferred to later boundaries.
