## 下一步真机优先验证
- 首先复测快速前后翻页（previous admission 毫秒级，780↔900 不导致 plan 取消，无真实 pressure 时 priority 0 短时复用）；真机首要复测 current 首帧稳定性（staticWarmDecodes/uploads 收敛到稳定 decode 角色/真实可见页，current 浅水位期间停止 speculative neighbor refill，decode/upload current handoff 避免后台长任务阻塞）。 2026-09-06 download storage boundary architecture baseline: a dedicated target architecture and normative contract now exist in `docs/DOWNLOAD_STORAGE_ARCHITECTURE.md` and `docs/DOWNLOAD_STORAGE_SPEC.md`. The refactor must remain split by functional boundary rather than accumulating another broad download patch. First implementation candidates are: (1) move shared network/local-read scheduler ownership above Pipeline construction without changing policy, then (2) make persistent local Reader reads genuinely streaming and remove the full-page remote `readPage()` byte-loader path. Preserve all pre-existing unstaged download fixes and keep each boundary in its own commit. Phase 1a implementation: `DownloadResourceCoordinator` now owns the production page `NetLane`; `local_media_composition.dart` injects it into `PipelineReaderSessionFactory`, and `app_runtime.dart` injects the same lane into persistent download composition. This is now constructor-enforced rather than convention-only: Reader factory requires `pageDownloadLane`, persistent composition requires `transferNet`, and `LiveCoordinator` requires `net`; none may silently allocate a fallback production lane. External transfer consumers must receive the identical physical-owner lane. Standalone `PersistentChapterDownloadService.open()` remains allowed to own an independent runtime/lane only when it is the complete isolated composition. Validation after this tightening: sessions/LiveCoordinator 27/27, focused pipeline_runtime 24/24, downloads composition/chapter suite PASS, LocalMedia ownership 1/1, and Home canonical-owner/projection 28/28 with the system SQLite library preloaded (the prior nine Home failures were Linux `flutter_tester` SQLite symbol resolution, not product failures). Phase 1b implementation is separate: the same coordinator now owns `ArtifactCacheReadScheduler`, injected into Reader factory and `PersistentDownloadComposition`. Phase 2 is also separate: cold persistent foreground artifacts now stream from `ArtifactCacheStreamEntry.open()` without `readAll` materialization, while memory hits remain direct. Phase 3 removes the App remote Reader `readyPageIndices/readPage` byte-loader registration while keeping origin response loaders; the next boundary is the generic local-loader/origin fallback contract and typed read-failure feedback, not storage-root migration. Phase 4 removes UI-owned dual-source recovery: `local_media_ui` rejects local-byte + origin-response registration for the same page; typed storage failure and artifact/transfer recovery are the next independent boundary. Phase 5a adds typed physical read failures and SAF bridge error identity.
