# Android Venera request-plan priority acceptance

Build the independent entry with current production dependencies:

```sh
TMPDIR=/path/to/disk/tmp flutter build apk --profile --split-per-abi \
  --target test/device_acceptance/venera_priority_runtime.dart
```

Run the companion runner with a same-certificate ordinary restore APK:

```sh
python3 apps/app/test/device_acceptance/venera_priority_runtime.py \
  --serial DEVICE_SERIAL --fixture-apk /path/to/fixture.apk \
  --restore-apk /path/to/ordinary.apk --out /path/to/evidence
```

Six cases use real loadComic/loadChapter page locators and source
resolveResourceControlled/onImageLoad through original NetLane controls,
canonical gate, Android Service/Binder and the single source WebView:

- 780/900 waiter jitter preserves the active760 plan until promotion to1000.
- An old current demotion to900 preempts only with a current1000 waiter.
- Ordinary820/600 active demotion and waiter780/900 jitter do not cancel.
- Physical permit transfer reads the latest waiter priorities, preserving rank order.
- A cancelled gate waiter never enters the WebView or cancels its active peer.
- Existing previous780 pressure and the original40-point rank boundary still work.

A source-created asynchronous timer and actual loopback Network.post marker
acknowledge hook/timer admission before test priority changes. Source request-plan
gate/runtime/hook/native-network diagnostics remain observation only. The
fixture uses no replacement TaskControl, gate, scheduler, native cancel hook,
concurrent WebView or test transport. The 500ms joined-exit observation applies
only to these timer-based cases; it is not a cross-source performance promise.

The fixture opens no user library, preferences or installed-source roster.
Export and compare complete backups before/after, retain actual wire evidence,
and restore the ordinary APK in finally. This scope does not prove real-origin
second-scale source-plan causes, URLConnection/DNS blocking-read cancellation,
original intermittent Reader loading, fixed-position stutter, GC/input latency
or final physical display performance.
